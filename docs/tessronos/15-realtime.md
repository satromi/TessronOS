# 第15章　実時間制御TAD

## 15.1 概要

実時間制御TADは、時間に沿って進むデータ(音楽の演奏、アニメーション、映像と音声の再生、字幕)をxmlTADで書いたものである。仕様はTADjs Desktopの「実時間TAD仕様」(`realtimeDataTAD.md`、バージョン1.7)に従う。実身のレコードの中の`<realtime>`要素が1つのプログラムで、その下の`<realData>`が順に実行される実時間データ、`<realGroup>`が時間を共有するイベントの組である。`<realtime>`はレコードの根(`<tad><realtime>`)にも、文章の中(`<tad><document><realtime>`)にも、図形の中(`<tad><figure><realtime>`)にも置ける。`<realtime>`の直下の`<figure>`は、プログラムが動かす図形、文字枠、画像を置く場面である。

TessronOSでは、実時間制御TADを次の3つの方法で再生する。

| 方法 | 内容 |
| --- | --- |
| MPEG Player | 実身をMPEG Playerのウインドウで再生する(11.12、15.5.1)。`<realtime>`だけのレコードの実身を開くと、既定でこれが使われる |
| スライド | スライドの1枚が実時間制御TADなら、その場で再生する(11.11)。仮身を持たない`<realtime>`の文章は、それ自身を1枚のスライドとして映す |
| 二進TAD | 実時間制御のセグメントを二進TADとxmlTADの間で相互に変換する(15.7)。書庫管理とバックアップが使う |

## 15.2 構成

| 部分 | 置き場所 | 動く所 | 役割 |
| --- | --- | --- | --- |
| 実行系 | `lib/librtad/`、`include/ts/rtad.h` | デスクトップ(カーネル) | `<realtime>`を読んでプログラムにし、時刻に従って実行する。描画も入出力もせず、ホストの関数を呼ぶ |
| 再生部 | `application/desktop/dtrt.c` | デスクトップ(カーネル) | 場面を組み、実行系の求めに応じて物を動かして描く。音と映像のプロセスを起動し、チャネルで指示する |
| プロセスのウインドウでの再生 | `application/desktop/dtrthost.c` | デスクトップ(カーネル) | MPEG Playerのウインドウに再生部を置き、MPEG Playerの依頼で操作する(15.5.1) |
| スライド | `application/desktop/dtslide.c` | デスクトップ(カーネル) | スライドの1枚として再生部を持つ |
| 実時間メディア | `application/rtmedia/` | プロセス | 音声ファイル(WAVE、MP3)、音符、MIDIメッセージ、PCMを混ぜてサウンドデバイス`snda`へ出す |
| MPEG Player | `ffmpeg_btron/tessron/mpegplay_ts.c`(別リポジトリ、パッケージ`etc/pkg/mpegplay.tpk`) | プロセス | 実時間制御TADの実身を開くアプリ(11.12)。`--embed`で起動されるとウインドウを持たず、映像を復号してメモリ実身へ書き、音声を鳴らす |
| 二進TADの変換 | `lib/libbpk/bpk_rt.c`、`bpk_tad.c`、`lib/libbtbk/btbk_tad.c` | ライブラリ | 実時間制御の要素とセグメントの対応表と、相互の変換 |

実行系と再生部をデスクトップの中に置いたのは、場面の描画がスライドと同じく文章と図形の表示部(`tv_doc_draw`、`tv_fig_draw`)を使うためである。表示部はカーネルの中にあり、プロセスからは図形しか描けない(11.11)。実行系はシステムコールを呼ばず、確保と解放もホストの関数で行うので、カーネルの試験とホストの試験の両方がそのままリンクして試験できる。カーネルは浮動小数点のレジスタを使わない(`-mgeneral-regs-only`)ので、実行系は整数だけで計算する。

音と映像はプロセスにした。音の合成と復号は浮動小数点を使い、MP3と映像の復号は重く、FFmpegはカーネルにリンクできない大きさと形(newlib、POSIXのスレッド)を持つ。プロセスに分けると、復号の遅れや異常がデスクトップを止めない。MPEG Playerは独立したパッケージなので、入っていなければ映像は再生できないが、実行系は`<video>`の`onerror`と`<fallback>`で代わりの処理を行う(15.6.1)。

## 15.3 プログラム(データの形)

`rt_new`は、`<realtime>`の要素のツリーをノードの列(プログラム)に読み替える。ノードは要素ごとに1つで、子を持つ要素(`<realGroup>`、`<if>`、`<while>`、`<random>`、`<interpolate>`、`<keyframes>`、`<trigger>`、`<onerror>`)は、子の範囲の終わりを持つ。読む時点で次のものを決める。

| もの | 内容 |
| --- | --- |
| 物(`RT_OBJ`) | プログラムが`ref`や`id`で名指す図形、文字枠(`<text id>`の文章)、画像、映像。位置(左上右下)、不透明度、回転、拡大率、反転、重なり順、表示の有無を持ち、記録された値を初期値として残す |
| メディア(`RT_MEDIA`) | `<audio>`と`<video>`。状態(待機、読込み中、準備済み、再生中、一時停止、終了、停止、異常)、属性のすべて、`<fallback>`の並び、再試行の回数を持つ。1つのプログラムで64まで |
| ストリーム(`RT_STREAM`) | `<stream>`の番号、`<deviceName>`、`<deviceParams>`、`<streamData>` |
| 単位系 | `<unitSystem>`の主単位と補助単位。時間の値は、そのときの単位系と補助単位、`<unitSpecTemp>`、`<unitScale>`、`<absoluteUnitCoeff>`、要素の`unit`属性(us、ms、s、min、tick)から、マイクロ秒に直す |
| 式 | `<expr>`を16ビットの逆ポーランドの符号列にする。定数は`0x8100`以上、変数はその番号、演算は`0x8000`台(仕様6.2の表)。0での除算は0 |

時刻はマイクロ秒の64ビット整数(`RT_TIME`)、値は100万分の1を単位とする整数(`RT_V`)、緩急の曲線(`function`)は65536分の1で表す。単位系の指定がないときの時間の単位はミリ秒、`tick`は単位系がなければ960分の1秒とする。変数は符号付き32ビットで、`0x4000`から`0x4007`はシステムの値(プログラムの時刻のミリ秒、乱数、最後に押したキー、ポインタの位置、再生中のメディアの数、スライドの番号、実行中の`<realData>`の番号)である。

## 15.4 実行

実行系は、`rt_step(rt, now)`を呼ばれるたびに`now`までに予定されたことをすべて行い、次に何かをする時刻を返す。何も動いていなければ外からのイベントを待つ(`RT_NEVER`)。滑らかに変わるものがある間は、次のフレーム(60分の1秒、`RT_FRAME_US`)を返す。

実行の単位はスレッドで、各スレッドは自分の時刻を持つ。`<realData>`は1本のスレッドで始まり、並列のグループ(`type="parallel"`)は親と同じ時刻から新しいスレッドとして子を実行し、親はグループの直後へ進む。直列のグループ(`serial`)は、子の実行が終わった時刻から親が続く。`<timeDelta>`はスレッドの時刻を進め、`<timeAbsolute>`はいちばん内側のグループの開始からの時刻にする(過去に戻る指定は無視する)。同じ時刻に予定されたものは、記録の順に行う。

| 要素 | 実行のしかた |
| --- | --- |
| `<label>`、`<jump>` | 跳び先は、自分とその外側の範囲から探し、なければプログラム全体から探す。`start`と`end`は`<realData>`の先頭と終わり。`next_slide`、`prev_slide`はスライドの移動をホストに頼む |
| `onended="jump:L"` | メディアの終わりでLへ跳ぶ。実行中のスレッドがLに着いたとき、そこへ跳ぶ予定のメディアや実行中のグループが先に残っていれば、それが終わるまでLで待つ。プレイリスト(10.5、10.9)の順次再生はこの規則で成り立つ |
| `<if>`、`<while>`、`<assign>` | 式を評価する。`<while>`の1回の繰り返しで時間が進まないときは、2万回ごとに1ミリ秒進めて止まらないようにする |
| `<random>` | 子から1つを選ぶ。`exclude="last"`は直前と同じものを除く。乱数はxorshift32で、`rt_seed`で種を与えると同じ選び方を繰り返す |
| `<interpolate>` | 2つの子(音符、図形の位置、制御の値)の間を`divisions`で分け、両端を含む`divisions+1`回を行う。間隔は`timeDelta`の指定による。`timeDelta`がなければ、与えた値から次の値までを1秒で進める(仕様の見本の補間はどれも時間を書いておらず、1分割を1フレームにすると、10分割の移動が0.2秒足らずで終わって飛んだように見えるため)。`function`は直線、スプライン(Catmull-Rom)、ease系、`cubic-bezier`。音符は高さ、強さ、長さを補間して順に鳴らす |
| `<keyframes>` | `offset`の百分率の位置の値の間を、キーごとの`function`で補間する。`iterations`、`direction`、`fill`、`delay`に従う |
| 制御(`audioControl`ほか) | メディアの再生、停止、音量、位置、物の位置、不透明度、回転、拡大率、表示、画像の差し替え、文字枠の内容。`duration`があれば、その時間をかけて変える |
| `<wait>` | クリック、キー、時間、メディアの終わりなどを待つ。待っている間、スレッドは進まない |
| `<trigger>` | 入力(click、dblclick、keydown、keyup、mouseenter、mouseleave、swipe、resize、visibility)で子を実行する。`once`、`enabled`、`<triggerControl>`で有効、無効を切り替える |
| `<groupControl>` | 名前のグループのスレッドを一時停止、再開、停止、最初から、速度の変更、位置の移動を行う。逆再生はアニメーションだけに働く |
| `<onerror>`、`<fallback>` | メディアの異常(見つからない、復号できない、時間切れ)で代わりの資源を試し、`retry`の回数だけ`retryDelay`後に読み直し、最後に`<onerror>`の子を実行する。`<realData>`の直下の`<onerror>`はプログラム全体の既定である |

`autoplay="false"`の`<realtime>`や`<realData>`は、場面を表示して待ち、利用者が再生を始めると(`rt_begin`)実行する。`<realData>`は記録の順に1つずつ実行し、`startDelay`、`loop`、`loopCount`に従う。音符が鳴り終わるまでは、その`<realData>`は終わらない。

一時停止(`rt_pause`)はプログラムの時刻を止め、再開で続きから進める。位置の移動(`rt_seek`)は、プログラムを最初から実行し直し、指定の時刻まで音を出さずに早送りする。早送りの間に始まるはずだったメディアは、その時刻からの位置で再生を始める。最初の`<interpolate>`と`fill="backwards"`のキーフレームの最初の値は、実行の前に物へ与える(場面が最初から正しい状態で見えるように)。

## 15.5 再生部

再生部(`dtrt_open`)は、レコードの場面を表示部で一度組み、ウインドウの中の矩形に収める。場面の大きさは`<realtime>`の`<figure>`の`<figView>`、なければ1920×1080で、矩形に収まる最大の倍率で中央に置く。

プログラムが動かさない物は、重なり順に従って何枚かの層に描いておき、動かす物(図形、文字枠、画像、映像)はそれぞれ1枚の絵(スプライト)に描く。スプライトは黒の地と白の地に2回描き、2枚の差からその点の不透明度を求める。スプライトは、場面の座標ではなく自分の範囲の左上を原点にした描画領域に描く。場面の外から滑り込む物(左端が負の位置から始まる画像など)も、場面の範囲で切られずに描ける。再生を始めた時には、物を最初の値(フェードで現れる物は不透明度0)にしてから場面全体を描き直す。こうすると文字の縁の中間の色も、下の物の上に正しく重なる。フレームごとに、変わった所(前の位置と新しい位置)だけ、層とスプライトを重なり順に、移動、回転、拡大、反転、不透明度を付けて合成し、ウインドウに書いて`wm_post`で画面に出す。描画はデスクトップのタスクを止めないよう、再生部のタスク(優先度19)が行う。

映像は、そのスプライトにMPEG Playerが書いたフレームを置く。`<video>`の矩形(画面の倍率をかけた大きさ、1280×720まで)をMPEG Playerに伝え、MPEG Playerはその大きさの中央に縦横比を保ってフレームを作る。ポスター(`poster`)は再生が始まるまで表示する。

利用者の操作は、場面の座標に直して実行系に渡す(`rt_input`)。クリックはその位置の物の`<trigger>`と`<wait event="click">`に、キーは`keydown`と`keyup`の名前(`Space`、`ArrowLeft`、`Enter`、`a`など)に、押したまま60単位以上動かして離すとスワイプになる。実行系が受け取らなかった操作は、スライドやMPEG Playerの操作として扱う。

### 15.5.1 プロセスのウインドウでの再生

MPEG Playerは、実時間制御TADの実身を開くと(プレイリストの曲として出会ったときも)、デスクトップへの依頼`DT_RQ_RT_OPEN`(`include/ts/dtreq.h`)で、自分のウインドウの映像の領域での再生を頼む。デスクトップ(`application/desktop/dtrthost.c`)は、依頼のウインドウがそのプロセスの作ったものであることを確かめ(`knl_wmobj_who`)、作業領域の左上から頼まれた大きさに場面を収め、スライドと同じ再生部(`dtrt_open`)でウインドウの描画環境に描く。MPEG Playerは映像の領域を描かず、下の帯だけを描く。場面の文章と図形を描く表示部はカーネルの中にあるので、プロセスに場面を描かせず、ウインドウを借りて描く形にした。

その後の操作は`DT_RQ_RT_DO`で、`recno`に何をするか(`DT_RT_*`)を書き、`carry`に`DT_RQ_RT_OPEN`の答えの`how`の番号を書く。その番号の再生は、依頼したプロセスからしか操作できない。

| `DT_RT_*` | すること |
| --- | --- |
| `STATE` | 何もせず、状態だけを答える |
| `TOGGLE`、`STOP`、`RESTART` | 再生と一時停止(待っているプログラムは始める)、停止、先頭から |
| `SEEK`、`TRACK` | `grab_x`ミリ秒進める(負なら戻す)、プレイリストの`grab_x`曲先(前)へ |
| `AREA`、`REDRAW`、`GROUND` | `look.w`×`look.h`に場面を置き直す、描き直す、背景色変更のパネル |
| `LIST` | プレイリスト表示のパネル。選んだものを再生する |
| `PRESS`、`RELEASE`、`KEY` | 作業領域の`grab_x`、`grab_y`での左ボタンの押下と解放、キー`grab_x`。`DT_RT_KEY_MINE`を付けたキーは、プログラムが受け取るときだけ渡す |
| `MOVE` | ポインタが作業領域の`grab_x`、`grab_y`にある(場面の外の座標なら、場面から出た)。`mouseenter`と`mouseleave`のため。MPEG Playerは40ミリ秒に1回まで送る |

答えは、`flags`に状態(`DT_RTS_PLAYING`、`PAUSED`、`WAITING`、`DONE`、受け取ったときの`TAKEN`)、`look.w`にプログラムの時刻(ミリ秒)、`look.h`にプレイリストの数、`text`に再生しているメディアの題名と作者である。MPEG Playerは250ミリ秒ごとに`STATE`で状態を聞き、`DONE`をリピートの設定に従って扱う。パネルは、プロセスのウインドウの上に出す(`dt_host_of`)。

プロセスが`DT_RQ_RT_CLOSE`で閉じるか、ウインドウがなくなる(プロセスの終了、強制終了)と、再生部を閉じ、音と映像のプロセスを終わらせる。ウインドウがなくなったことは、デスクトップの主ループ(`dt_rthost_poll`)と次の依頼で見つける。それまでの間にウインドウの番号が別のウインドウのものになっても描かないよう、再生部は描くたびに、その番号のウインドウの実身のUUIDが開いたときのものかを確かめる(`dtrt_host`)。同時に4つまで再生できる。コンソールには`player: hosted 番号 in a window of process 番号`、操作ごとに`player: 番号 op 名前`、閉じると`player: 番号 closed by its process`(または`with its window`)を出力する。

## 15.6 メディアの経路

再生部は、音と映像を担当するプロセスを、プログラム実身から`ob_cre_obj`で起動する。引数(`RTM_ARG`、`include/ts/rtmedia.h`)は、指示を書くチャネル、答えを読むチャネル、映像ならフレームを置くメモリ実身のUUIDである。指示(`RTM_CMD`)は資源を開く、再生、一時停止、再開、停止、位置、音量、定位、速度、消音、閉じる、音符、MIDI、ストリーム、PCM、大きさ、終了で、答え(`RTM_A_*`)は読み込み完了(長さと映像の大きさ)、再生中、一時停止、終了、異常、位置、フレーム、起動完了である。資源は、`{realId}_0_1.mp3`のように実身の資源の名前で、または取り込んだファイルの実身のレコードで指す。

時刻は単調時計のナノ秒で渡す。実時間メディアは、すべての音を指示の時刻から一定の80ミリ秒後に鳴らすので、2つの音の間隔はプログラムのとおりになる。映像も同じ遅れで表示されるので、音と映像は合う。音のプログラムがあるときは、実時間メディアが起動完了を答えるまで(最大3秒)、プログラムの開始を待つ。

### 15.6.1 映像

映像はMPEG Player(`mpeg-player`)を`--embed`で起動して再生する。起動されたMPEG Playerはウインドウを作らず、指示のチャネルを読み、資源を開いて長さと大きさを答え、再生の指示でFFmpegの復号を始める。音声はMPEG Player自身が`snda`へ出し、フレームはメモリ実身のレコード0の2つの面に交互に書き、ヘッダ(`RTM_FRAMES`)に書いた面を名指して、答えのチャネルで通知する。WAVEとMP3以外の音声ファイル(AAC、Ogg、FLACなど)も、MPEG Playerで再生する。`<video>`1つにつき1つのMPEG Playerが動く。

MPEG Playerのパッケージが入っていなければ、映像と、実時間メディアが復号できない形式の音声は、資源を開いた時点で「対応しない形式」の異常になる。`<fallback condition="unsupported">`があればそれを試し、なければ`<onerror>`を実行する。メディアの`onended`で次へ進むプログラムは、異常でも次へ進む。

### 15.6.2 実時間メディア

実時間メディア(`application/rtmedia/`、プログラム実身のレコード1)は、3つのタスクを持つ。主タスクが指示を読み、読込みタスクが資源を読んで48kHz、ステレオ、16ビットに復号し(WAVEは8、16、24、32ビットと浮動小数点、MP3はminimp3)、混合タスクが5ミリ秒ずつ音を作って`snda`へ書く。音量、定位、速度、ループ区間、フェードイン、フェードアウトは混合タスクが行う。

### 15.6.3 音源

MIDIの機器はないので、音符とMIDIメッセージはすべてソフトウェアで合成する。General MIDIの音色の系統ごとに作り方を決めてあり、ピアノ、ベース、ベルは減衰する倍音、オルガン、弦、金管、リード、フルートは持続する倍音、ギターは撥弦(遅延線の平均)、チャネル10のドラムは周波数を下げる正弦(バスドラム、タム)とフィルタを通した雑音(スネア、シンバル)である。ストリームの`<deviceName>`が`inst:Piano`のような名前なら、その音色で鳴らす。`synthX:`は`<deviceParams>`の波形(sine、square、saw、triangle、noise)と包絡線で鳴らす。MIDIメッセージは、ノートオン、ノートオフ、プログラムチェンジ、コントロールチェンジ(音量、パン、サステイン、全音停止)、ピッチベンドを解釈する。

## 15.7 二進TAD

実時間制御の要素は、仕様11章のセグメントIDとSUBIDの二進TADになる(`TS_RGRP`は`0xFFD0`、`TS_REAL`は`0xFFEA`のように、表の値に`0xFF00`を加えたもの)。セグメントの本体の形は仕様にないので、TessronOSでは次のように決めた。

| 位置 | 内容 |
| --- | --- |
| 最初のワード | SUBID×256+フラグ。フラグ1は、要素の中の要素が後に続き、終わりのセグメントで閉じることを示す |
| 名前 | SUBIDを持たない要素(`<then>`、`<expr>`、`<deviceName>`など)だけ。`TS_REAL`のSUBID `0x10`で、16ビットの長さと名前 |
| 属性 | 16ビットの数、続いて属性ごとに16ビットの長さと名前、32ビットの長さと値。文字列はUTF-8で実体参照を戻し、奇数の長さは1バイト詰める。要素の文字は名前の空の属性 |

SUBIDの表で終わりを持つ要素(`<realGroup>`、`<if>`、`<while>`、`<random>`、`<interpolate>`、`<keyframes>`、`<trigger>`、`<onerror>`、`<realData>`)は表の終わりのSUBIDで、それ以外は`TS_REAL`のSUBID `0x11`で閉じる。仕様の表に`<realtime>`、`<stream>`、`<eventArray>`、`<else>`、`<figureRef>`の番号はないので、`TS_REAL`のSUBID 2と`TS_REALEND`のSUBID 2を`<realtime>`に、`TS_REAL`のSUBID 1を`<stream>`に、`TS_RGRP`のSUBID 4と5を`<eventArray>`に、`TS_BRLP`のSUBID 10を`<else>`に、`TS_MEDIA`のSUBID 4を`<figureRef>`に充てた。要素の間の文字は`TS_REAL`のSUBID `0x12`である。

`TS_MEDIA`(`0xFFA0`、ソースでは`TS_RMEDIA`)と`TS_MCTL`(`0xFFB0`、`TS_RMCTL`)は、文章のページ割付け(`TS_TPAGE`)と図形要素(`TS_FPRIM`)と同じ番号なので、実時間制御の要素のすぐ内側にあるときだけメディアとメディア制御と読む。プログラムが図形や文字枠を名指す`id`属性は二進TADの図形要素にないので、`id`を持つ図形、画像、文字枠、`<text>`の直後に`TS_REAL`のSUBID `0x13`(要素の名前とid)を置き、xmlTADに戻すときに直前のその要素へ`id`を付け直す。文章の中の`<realtime>`は段落の間に置く。xmlTADから二進TADへ、二進TADからxmlTADへと変換したものは、もう一度変換しても同じバイト列になる。

## 15.8 仕様への対応

| 仕様の章 | 対応 |
| --- | --- |
| 1 概要、文書構造の3つの型 | すべて。図形TADの中の`<realtime>`は、その図形を場面とする |
| 2 ルート要素の属性 | `autoplay`、`preload`、`loop`(全体の繰り返し)。`preload="none"`の資源は再生の直前に読む |
| 3 `<realData>`、`<stream>`、デバイス名、複数のブロック | すべて。デバイス名は`inst:`、`MIDIn:`、`synthX:`、`audio:`、`display:`を解釈する |
| 4 `<realGroup>`、入れ子、`<eventArray>` | すべて。`<eventArray>`の中のイベントは、それが置かれたスレッドでその場で順に実行する |
| 5 `<timeDelta>`、`<timeAbsolute>` | すべて |
| 6 式、`<label>`、`<jump>`、`<if>`、`<while>`、`<assign>`、`<random>` | すべて。式の演算は6.2の表のすべて |
| 7 `<interpolate>` | 音符、図形の位置(`<figureRef>`)、制御の値。MIDIメッセージの補間はしない(両端の値をそのまま送る) |
| 8 単位系 | すべて |
| 9.1〜9.4 音符、MIDI、PCM | すべて。音源はソフトウェアの合成(15.6.3) |
| 9.5〜9.7 `<audio>`、`<video>`、`<image>` | 属性のすべて。映像はMPEG Playerがあるとき。メタデータ(`title`、`artist`、`album`、`trackNumber`)はプレイリストに表示する |
| 9.8〜9.12 制御 | すべての命令。`playbackRate`は音声だけで、映像は1倍のまま |
| 9.13 `<wait>` | すべてのイベント |
| 9.14 `<keyframes>` | すべて |
| 9.15 `<trigger>`、`<triggerControl>` | すべてのイベント。`visibility`はウインドウの表示と非表示、`resize`はウインドウの大きさの変化 |
| 9.16 `<onerror>`、`<fallback>` | すべて。`condition="slow"`は、ネットワークから資源を取らないので当てはまらない |
| 9.17 `<groupControl>` | すべて。`reverse`はアニメーションだけを逆に進める |
| 10 使用例 | 10.1〜10.9のすべてを、見本の実身「実時間TAD見本」で再生できる(15.10) |
| 11 バイナリとの対応 | すべてのセグメント(15.7) |
| 12 実装上の考慮事項 | 12.1の解析の注意、12.2の時刻の精度(マイクロ秒、音はサンプル単位)、12.3の互換性(知らない要素と属性は無視する) |

## 15.9 制限

音と映像の遅れは一定の80ミリ秒と見なしており、機器ごとの実際の遅れは測らない。映像は1つの`<video>`につき1つのプロセスで、同時にいくつも再生すると重い。フレームは1280×720までの大きさで作り、それより大きく表示するときは拡大する。位置の移動は最初から実行し直すので、長いプログラムでは時間がかかる。MIDIの外部機器、`<streamData>`による音色の読込み、インターネット上の資源(`http:`)には対応しない。

## 15.10 試験

カーネルの試験の`rt`グループ(`tests/ktest/ktest_rt.c`)は、実行系をテスト用の時計で1ミリ秒ずつ進め、数値と名前の変換、要素の読込み、式、分岐と繰り返しとラベル、単位系、補間、種を与えた`<random>`、メディアの読込みと異常と代替、トリガー、待機、キーフレーム、一時停止と位置の移動、スライドの移動の依頼を、鳴った音と求められた操作の時刻で確かめる。メディアは5ミリ秒で読み込めて3秒で終わるものとし、名前に「missing」を含むものは見つからないことにする。続いて同じレコードを二進TADにし、xmlTADに戻し、もう一度二進TADにして同じバイト列になること、戻したレコードが元と同じに実行されることを確かめる。

見本の実身「実時間TAD見本」(仮身サンプルの中、`etc/xtad/01a0d8c5-6a00-*`)は、仕様10章の9つの例を1枚ずつのスライドにしたもので、例ごとの実身(`01a0d8c5-6a01-*`から`6a09-*`)は音声(MP3)、映像(H.264とAACのMP4)、画像(PNG、JPEG)の資源を持つ。画面は、見本を順に再生する`tools/tests/ui_rt.steps`と、MPEG Playerのウインドウでの再生、操作、大きさの変更、仮身の「実行」を確かめる`tools/tests/ui_rt_player.steps`を`tools/ui_run.py`で実行して確認する(12.4)。カーネルの試験の`dtwin`の群の`test_player`は、見本をMPEG Playerで開き、クリックとSpaceがデスクトップへ渡ること、大きさを変えると場面を置き直すこと、Ctrl+Eで閉じたときとプロセスを終わらせたときに再生部が閉じることを確かめる。`--wav`を付けると鳴った音をWAVEファイルで確かめられ、プレイリストの曲の周波数とMPEG Playerの映像の音が記録される。また、`tools/tests/test_bpk.py`と`test_btbackup.py`は、二進TADの変換を表とともにホストでビルドして試験する。
