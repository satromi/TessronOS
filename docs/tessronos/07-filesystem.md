# 第7章　ファイルシステム

## 7.1 2つのファイルシステム

TessronOSは2つのファイルシステムを持つ。システムの実身を格納するTSFSと、ブートパーティションと外部メディアに使うFATである。

| | TSFS | FAT |
| --- | --- | --- |
| 用途 | 実身の格納 | ブートパーティション、PCとデータをやり取りするメディア |
| 名前 | 実身はUUIDで開く。ディレクトリツリーはない | パスで開く |
| 形式 | TessronOS独自。ジャーナルとチェックサムを持つ | FAT12、FAT16、FAT32。長いファイル名に対応 |
| API | 実身の基本操作`ob_`(第8章) | T2EX互換の`fs_` |

## 7.2 fs_

`fs_`はT2EXのファイル管理の関数である。`fs_open`、`fs_read`、`fs_write`、`fs_close`、`fs_mkdir`、`fs_rename`、`fs_stat`などでFATのボリュームを扱う。マウントテーブルは全体で1つで、`/boot`にSDカードの第1パーティション(QEMUでは試験用ディスクのFATパーティション)がマウントされる。USBメモリは、デバイスの実身を通して要求すると`/media`の下にマウントされる(6.1)。

ファイルディスクリプタはプロセスごとに持ち、プロセスが終了すると閉じる。プロセスの`fs_read`と`fs_write`は256KBずつに分割して実行する。

FATは、電源断の後にマウントしたとき、クラスタチェーンとディレクトリエントリのサイズの不一致など、書込み途中で残った不整合を検査して修復する。

## 7.3 TSFS

TSFSは、実身の構造をそのままディスク上の形式にしたファイルシステムである。GPTのパーティションに置き、パーティションタイプGUIDは`54465331-0000-4000-8000-5446532d5631`である。

実身は次の要素からなる。

- 管理用セグメント。名前、日時、保護情報、レコードの並びと型、アプリケーションが格納する設定(`applist`、`window`、`tessronos.*`など)を持つJSONである。
- アイコン。ICOかPNGで、64KBまで。
- レコードの列。レコードは型(0〜31)とサブタイプを持つバイト列で、任意の位置に挿入と削除ができる。型1はxmlTADで、その中の`<link>`が仮身である。
- リソース。レコードに付随する画像、音声、動画である。
- 仮身表。この実身が含む仮身の一覧で、TSFSが型1のレコードから生成する。

実身はUUIDのversion 7で識別し、B+木でUUIDから検索する。時計が設定される前(電池のない機械で、SNTPで時刻を合わせる前)に作る実身は、時刻を含まない乱数だけのversion 4のUUIDで識別する。キャビネットは仮身を並べた実身であり、ファイルシステム側にディレクトリはない。

TSFSは仮身表から、各実身を指している仮身の数(参照数)を自動で数える。アプリケーションは参照数を操作しない。参照数が0になった実身は屑実身になり、空き領域が減ったとき、または要求されたときに回収される。

### 格納方式

TSFSには2種類の格納方式がある。

| 格納方式 | 形式 |
| --- | --- |
| ネイティブ | GPTのパーティションをTSFSの形式で使う。システムボリュームはこの方式 |
| FAT上 | FATのディレクトリに、実身を1つずつTADjs Desktopと同じ形式のファイル群で格納する |

FAT上の格納方式のファイル群は次の形式である。この形式で書き出せば、TADjs Desktopで開ける。

| ファイル | 内容 |
| --- | --- |
| `{UUID}.json` | 管理用セグメント |
| `{UUID}_0.xtad` | 位置0のレコード(xmlTAD) |
| `{UUID}_N.xtad`、`{UUID}_N.bin` | 位置Nのレコード(`.bin`は型1以外) |
| `{UUID}.ico` | アイコン |
| `{UUID}_N_M.png`など | 位置Nのレコードのリソース |

### 障害耐性

ネイティブのTSFSは、電源断が起きても管理構造が壊れないように設計してある。

- 管理ブロックはすべてチェックサム(CRC32C)を持つ。読み込んだブロックのチェックサムが合わなければ、ボリュームを読取り専用に切り替え、以後は書き込まない。
- 変更はジャーナルに書いてから本来の位置に書く。マウント時にジャーナルを再生するので、途中で中断した変更は、すべて反映されるか、まったく反映されないかのどちらかになる。
- スーパーブロックは2つを交互に書き、さらにバックアップを持つ。
- 開いたまま削除された実身や、仮身表を再構築している途中の実身は孤児リストに登録し、マウント時とアンマウント時に後処理する。

`tools/fsck.tsfs`がボリュームを検査し、`tools/mktsfs`がボリュームを作成する。どちらもPythonで書かれ、ホストで動く。
