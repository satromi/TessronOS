# 第5章　プロセスとシステムコール

## 5.1 プロセス

プロセスは、固有のアドレス空間と、その中で動く1つ以上のタスクからなる。タスクはすべて保護レベル3(EL0)で実行される。

プロセスはELF64のプログラムから生成する。プログラムは`0x400000`にリンクした静的なELFで、パスで指定する(`ts_cre_prc`)か、実身とそのレコードで指定する(`ts_cre_prc_obj`)。TessronOSでは、プログラム実身のレコード1に実行ファイルを格納するのが標準の形で、仮身を開くとデスクトップがこれを使ってプロセスを起動する(第11章)。

| システムコール | 機能 |
| --- | --- |
| `ts_cre_prc`、`ts_cre_prc_obj` | プログラムをロードし、メインタスクを生成して実行する。起動時の引数を渡せる |
| `ts_get_arg` | 起動時の引数を受け取る |
| `ts_ext_prc` | 自プロセスを終了する |
| `ts_ter_prc` | 別のプロセスを強制終了する |
| `ts_wai_prc` | プロセスの終了を待ち、後処理をする |
| `ts_ref_prc`、`ts_get_pid` | プロセスの状態とプロセスIDを取得する |

プロセスは同時に32000個まで生成できる(`CNF_MAX_PRC`)。実際にはその前にメモリが不足する。プロセスにはタスクごとに64KBのシステムスタックとユーザスタック、アドレス空間のページテーブル、プログラムイメージが必要なので、何もしない小さなプログラムでもおよそ200KBを使う。メモリ2GBのマシンでは数千のプロセスが同時に動く。プロセスIDは1から32767までを順に使い、一巡したら空いている番号を再利用する(`CNF_PID_MAX`)。

起動時、呼び出す側はプロセスの優先度と、渡す引数を指定する。メインタスクはプログラムのエントリ`_start`から実行を始め、`main`を呼ぶ。`main`から戻るか、いずれかのタスクが`ts_ext_prc`を呼ぶと、プロセス全体が終了する。

プログラムのロードでは、新しいアドレス空間を作り、ELFの`PT_LOAD`セグメントをそこへ読み込み、起動時の引数のページを置く。ここまでは、プロセスの表を守るロック(`proc.c`の`prc_mtxid`)を持たずに行う。このロックは、プロセスのタスクがファイル、実身、描画、ウインドウのシステムコールに出入りするたび(5.5)と、`ts_get_pid`が呼出し元を調べるたびに取られるので、読込みの間これを持っていると、100MBを超えるプログラムを読む数秒のあいだ、ほかのすべてのプロセスとデスクトップが止まる。読み終えてから、ロックの中でプロセスIDと制御ブロックを割り当て、空間を制御ブロックに渡してメインタスクを生成する。それまで新しい空間はどこからも見えない。プロセスの数が上限に達しているときは、読む前に`E_LIMIT`を返す。

実行ファイルは256KBずつカーネルのバッファに読み、そこからアドレス空間のページへ写す。ページは物理的に連続していないので、直接は読み込めない。1ページずつ読むと4KBごとに実身とレコードを探し直すことになり、118MBのブラウザのロードにQEMUで8〜12秒かかっていた。256KBずつ読むと約1.4秒である。

## 5.2 プロセスのタスクとオブジェクト

プロセスは`tk_cre_tsk`で自分のタスクを生成できる。タスクは必ず保護レベル3でプロセスのアドレス空間に置かれ、浮動小数点演算を使える。ユーザスタックはデフォルトで64KB、最大1MBで、プロセスのアドレス空間に確保する。

プロセスが生成したセマフォ、イベントフラグ、ミューテックス、メッセージバッファ、タスクは、そのプロセスの中でだけ有効である。別のプロセスやカーネルのオブジェクトのIDを渡すと`E_ID`になる。プロセス間の通信には、プロセスメッセージ(5.4)、通信用の実身、共有メモリ、イベント通知を使う(第8章)。

1つのプロセスが持てるオブジェクト数は、タスクとイベントフラグが256、セマフォとミューテックスが1024、メッセージバッファが64である(`include/ts/proc.h`の`TS_PRC_*_MAX`)。これを超えるか、カーネルのテーブルがカーネル自身の予約分を残して埋まると、生成のシステムコールが`E_LIMIT`を返す。

POSIXスレッドは`lib/libpthread`が提供する。スレッドはプロセスのタスクとして実装し、ミューテックスや条件変数は競合がなければユーザ空間のアトミック操作だけで処理する。

## 5.3 メモリ

プロセスのアドレス空間の配置は4.6のとおりである。プログラムイメージはロード時にマッピングし、ヒープはその上に伸ばす。それ以外のメモリは`ts_map_mem`でアドレス範囲を予約し、使う部分をコミットして確保する。

| システムコール | 機能 |
| --- | --- |
| `ts_map_mem` | アドレス範囲を予約する。保護属性に`TS_MEM_READ`か`TS_MEM_RW`を指定すれば、ただちに0で初期化したページをマッピングする。`TS_MEM_NONE`ならアドレス範囲だけを予約する |
| `ts_ctl_mem` | 予約範囲内のページをコミットする、保護属性を変える、解放する |
| `ts_unm_mem` | ページを解放し、予約を解除する |

書込みと実行を両方許すページは作らない。実行属性(`TS_MEM_EXEC`)を要求すると`E_NOSPT`になるので、プログラムが実行時にコードを生成して実行することはできない。

プロセス間で共有するメモリは、揮発性の記憶実身のレコードを`ob_map_rec`で共有メモリ領域にマッピングして作る(第8章)。共有メモリはどのプロセスからも同じアドレスに見える。

## 5.4 プロセスメッセージ

プロセスはそれぞれメッセージの受信口を1つ持つ。`ts_snd_msg`でプロセスIDを指定して送信し、`ts_rcv_msg`で受信する。1通は256バイトまでで、8通までキューにためられる。キューが満杯のときの送信と、空のときの受信は、指定した時間まで待つ。

子プロセスが終了すると、親プロセスに`TS_MSG_CHILD_EXIT`が届く。

## 5.5 プロセスの終了

プロセスは次のいずれかで終了する。

- `main`から戻る、または`ts_ext_prc`を呼ぶ。
- 別のプロセスが`ts_ter_prc`を呼ぶ。デスクトップでShift+Pauseを押したときも、同じ処理で終了する(5.5.1)。終了コードは`ts_ter_prc`に渡した値で、Shift+Pauseでは`TS_ABORT_TERM`である。
- EL0で例外を起こす。未定義命令(例外クラス`0x00`。`UDF`と割り当てのない命令)と不正な実行状態(`0x0e`)では`TS_ABORT_ILL`、それ以外の例外(データアボート、命令アボート、アライメント例外など)では`TS_ABORT_FAULT`が終了コードになる。コンソールには例外の種類、アドレス、`ELR`とともに`LR`(x30)も表示する。0番地へ分岐した例外では、呼び出した場所は`LR`にしか残らないためである。
- システムコールに渡したアドレスで、カーネルがデータアボートを起こす。そのアドレスがプロセスの空間内にあり、マッピングされていないか書き込めないときは、そこに中身のないページを割り当ててシステムコールを最後まで実行させ、戻るところでプロセスを`TS_ABORT_FAULT`で終了させる。

終了時、カーネルはプロセスのタスクとオブジェクトを削除し、開いていたファイル、ソケット、実身のキーを閉じ、プロセスが作ったウインドウ(従属ウインドウを含む)を閉じ、アドレス空間を破棄する。タスクがファイルや実身のシステムコールの処理中にあるときは、途中で止めるとボリュームやロックが不整合な状態で残るので、システムコールから戻るところまで進めてから止める。長い読み書きは256KBごとに区切り、区切りごとに終了要求の有無を確認する。

### 5.5.1 キーボードからの強制終了

デスクトップでShift+Pauseを押すと、最前面のウインドウを作ったプロセスを強制終了する。最前面のウインドウとは、入力フォーカスを持つウインドウ、どのウインドウも入力フォーカスを持たなければ、ポップアップを除いて最も手前にあるウインドウである。ウインドウを作ったプロセスは、ウインドウの実身が生成時に記録したプロセスID(`wmobj.c`の`maker`)でわかる。終了は`knl_prc_force_end`が`ts_ter_prc(pid, TS_ABORT_TERM)`で行うので、システムコールの処理中のタスクの扱いも、ウインドウを閉じる処理も`ts_ter_prc`と同じである。結果はメッセージ行に「<プログラム名>(pid N)を強制終了しました」と表示し、コンソールにも1行出力する。プログラム名は、起動したプログラムの実身の名前、実身から起動していなければプログラムのファイル名である。

キーはウインドウマネージャの`wm_read_event`で処理する。ここはキーボードとポインタの入力がウインドウあての事象に変わる唯一の場所で、入力フォーカスと重なり順を知っている。デスクトップの主ループでも、パネルを操作する間のループでも入力は必ずここを通るので、どの状態でも同じように働く。HIDのドライバの中では、USBの転送の完了を処理する文脈でプロセスを終了させることになり、ドライバがウインドウを知る必要も生じるので、そこでは処理しない。Shift+Pauseとそのキーを離した事象はどのウインドウにも渡さない。キーを押し続けるとキーリピートで押下が繰り返されるが、終了させるのは最初の押下の1回だけで、キーを離すまで次のプロセスは終了させない。

次の場合は何も終了させず、メッセージ行にその旨を表示する。

| 場合 | 表示 |
| --- | --- |
| 最前面のウインドウがカーネルのもの(デスクトップ、キャビネット、基本文章編集、基本図形編集などカーネルのタスクとして動くもの)、またはウインドウがない | 強制終了できるプロセスがありません |
| システムに必要なプロセス | <プログラム名>(pid N)はシステムのプロセスなので強制終了できません |
| すでに終了処理中のプロセス | <プログラム名>(pid N)は終了の途中です |

システムに必要なプロセスは、initと、属性`TS_PRC_SYSTEM`を指定して起動したプロセスである。initは`knl_start_init`がこの属性で起動する。この属性は、プロセスでない呼出し元(カーネルのタスク)が`ts_cre_prc`に指定したときだけ有効で、プロセスが子プロセスに指定しても無視する。プログラムが自分の子プロセスを強制終了から保護できないようにするためである。

### 5.5.2 例外による終了の通知

プロセスが例外で終了すると、デスクトップがダイアログ「プログラムの異常終了」で知らせる(11.1)。例外ハンドラは画面を操作しない。プロセスを終了させるときに、プロセスID、例外を起こしたタスク、プログラムの実身とファイル名、`ESR`、`FAR`、`ELR`、`LR`、終了コードを記録するだけである(`include/ts/proc.h`の`T_PRCFLT`)。EL0の例外は`knl_prc_abort`で、システムコールに渡したアドレスによる例外は、プロセスが終了するシステムコールの出口(`knl_prc_call_leave`)で記録する。後者の`ELR`と`LR`はカーネル内の値である。

記録はカーネル内の4件のキューに入れ、デスクトップのタスクが主ループのたびに`knl_prc_fault_take`で取り出す。キューが満杯のときは最も古い記録を捨て、捨てた件数を数える。記録するのはプロセスを終了させた例外だけで、すでに終了処理中のプロセスの別のタスクが起こした例外は記録しない。そのため、例外が続けて起きても記録とダイアログが際限なく増えることはない。デスクトップが起動する前に起きた例外は、コンソールへの表示だけになる。

カーネルのタスクがEL1で例外を起こしたとき(`!EXCEPTION!`)は、例外の種類とレジスタをコンソールに表示し、そのプロセッサを割込み禁止のまま停止する。カーネルのデータが壊れている可能性があり、処理の継続を前提にしていないので、ダイアログは表示しない。SError、FIQ、タスクのスタックあふれ(`!STACK!`)も同じく停止する。例外として扱わずに処理を続けるのは、上に述べた、システムコールに渡されたプロセスのアドレスによるデータアボートだけである。

## 5.6 システムコール

EL0からカーネルを呼ぶにはSVC命令を使う。レジスタ`x8`に機能コード、`x0`から`x5`に引数を置いて`svc #0`を実行すると、`x0`に戻り値が返る。機能コードは上位16bitがクラス、下位16bitがクラス内の番号である。

| クラス | 接頭辞 | 内容 |
| --- | --- | --- |
| 0 | `tk_` | T-Kernelのシステムコールのうち、プロセスに許可するもの |
| 1 | `ts_` | プロセス、メモリ、プロセスメッセージ、単調時刻、UUID、乱数 |
| 2 | `fs_` | ファイル |
| 3 | `dt_` | カレンダ |
| 5 | `so_` | ソケット |
| 6 | `tm_` | デバッグ用のコンソール出力 |
| 7 | `ob_` | 実身 |
| 8 | `dp_` | 自分のウインドウへの描画 |
| 9 | `wm_`、`mn_`、`kc_` | ウインドウ、メニュー、かな漢字変換、外観設定テーブル |

クラス4(プログラムのロード`pm_`)は番号だけを予約してあり、まだ使っていない。

カーネルは、渡されたポインタがプロセスのアドレス空間内を指しているかを検査してから使い、プロセスのメモリにはコピー関数を通してだけアクセスする。検査に失敗すると`E_MACV`を返す。

プロセス側の呼出し口は`lib/libts`にある。`svc_stub.S`が各システムコールのスタブを、`crt0.S`がプログラムのスタートアップを受け持つ。一覧は付録Aにある。

## 5.7 ライブラリ

プロセスのプログラムは、目的に応じて次のライブラリをリンクする。

| ライブラリ | 内容 |
| --- | --- |
| `lib/libts` | SVCのスタブ、スタートアップコード、最小限のC関数 |
| newlib | 標準Cライブラリと数学関数。システム依存部(`_sbrk`、`_write`など)はプログラム側でリンクする |
| `lib/libcxxrt` | C++ランタイム(例外、RTTI、静的初期化)と、POSIXの関数(ファイル、ディレクトリ、ソケット、`mmap`、時刻など)。`eventfd`と`epoll`はプロセスの中で実現する(記述子は`0x3000`からの範囲で、ソケットやファイルの監視はしない) |
| `lib/libpthread` | POSIXスレッド |
| `lib/libjson` | JSONの解析 |
| `lib/libconf` | 設定用の実身の行の読み書き |
| `lib/libui` | データボックスのパネルでウインドウを構成する(第10章) |
| `lib/libbpk`、`libbtbk`、`libtxc`、`libxfu`、`libftp` | 書庫、文字コード、ファイルと実身の変換、FTP |
