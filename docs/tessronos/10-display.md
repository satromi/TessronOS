# 第10章　表示とウインドウ

## 10.1 構成

画面まわりは外核の3つの管理機能からなる。描画管理`dp_`、フォント管理`fn_`、ウインドウマネージャ`wm_`である。いずれもEL1で、呼び出したプログラムのコンテキストで実行される。プロセスからはSVCクラス8と9、それにウインドウの実身の操作(クラス7)で使う。

```text
 プロセス             ウインドウの実身(ob_) / dp_ / wm_・mn_・kc_ のSVC
 ───────────────────────────────────────────
 ウインドウマネージャ  ウインドウ、枠、合成、部品、パネル、メニュー、データボックス、
                      外観設定テーブル、ポインタ、メッセージ行、トレー
 描画管理 dp_        描画環境、塗りつぶし、線、図形、領域、ピクセル転送
 フォント管理 fn_     FreeType。グリフを生成し、描画環境に描く
 画面ドライバ         オフスクリーンバッファとディスプレイへの転送
```

## 10.2 描画

描画はすべて描画環境(番号`gid`)に対して行う。描画環境は、描画先のピクセル、座標の原点、描画可能な範囲(フレームとクリッピング領域)、色、描画モード(上書き、排他的論理和、論理積)を持つ。ウインドウはそれぞれ専用の描画環境とピクセルバッファを持つので、ほかのウインドウに覆われても内容は失われない。

| 分類 | 主な関数 |
| --- | --- |
| 塗りつぶしと線 | `dp_fill_rect`、`dp_frame_rect`、`dp_line`、`dp_line_wide` |
| 図形 | `dp_fill_poly`、`dp_draw_poly`、`dp_fill_round`、`dp_frame_round`、楕円、扇形、弓形、円弧、シード塗りつぶし |
| 領域 | `dp_rgn_*`。行ごとの区間で表した領域 |
| ピクセル | `dp_put_argb`、`dp_get_argb`、`dp_put_mono`、`dp_put_gray` |
| パターン | 2色の網掛け(8段階)か、タイルと透過マスク |

画像はPNG、JPEG、BMP、GIF、ICOをデコードでき、PNGへのエンコードもできる(`img_`)。

画面そのものは実身「画面」である(8.4)。解像度、色深度、選択できる解像度はそのレコード1で読み、解像度の変更はそこに書く。デスクトップが起動時に機器の設定の解像度にするときも、システム環境設定が解像度を表示するときも、この実身を通す。描画管理とウインドウマネージャは画面ドライバの関数を直接使う。

プロセスは、自分が作成したウインドウの描画環境(`wm_obj_gid`で取得する)にだけ、次の関数で描画できる。

| 関数 | 機能 |
| --- | --- |
| `dp_fill_rect`、`dp_frame_rect`、`dp_line` | 塗りつぶし、枠、線 |
| `dp_put_argb` | ピクセルを書き込む |
| `dp_text`、`dp_text_width` | システムフォントで文字列を描く、幅を求める |
| `dp_draw_tad` | xmlTADを描く |
| `dp_img_decode` | 画像をデコードする |
| `wm_obj_flush` | 描画した内容を画面に反映する |

## 10.3 フォント

フォントはFreeTypeで扱う。TrueTypeとOpenType(CFFを含む)を読み込め、グリフは256階調で生成し、背景のピクセルとアルファブレンドして描く。フォントはシステムボリュームのフォントの実身から読み込む。一度生成したグリフはキャッシュする。

フォントの実身は書体箱からリンクしてあり、実身名かメタデータの`tessronos.file.name`で名前が付いている。デスクトップは起動時に書体箱のリンク先をすべて開き、システムのフォントを`ob_fnd_lnk`で名前(`NotoSansJP-Regular.otf`、`NOTOSANS.OTF`、`KOGANEI.TTF`の順)から選ぶ。壁紙も同じように壁紙箱から`TESSRON.PIC`を探し、なければ最初のリンク先を使う。自分で文字を描くプロセスは`ts_face_find`、`ts_face_list`(`include/ts/face.h`)で書体箱からフォントの実身を得る。どちらも箱のリンクを名前で探す`ob_fnd_lnk`、`ob_lst_lnk`(8.3)を使う。

FreeTypeは複数のタスクから同時に呼んではならないので、フォント管理全体を1つのロックで保護する。サイズを設定して文字を描くような一連の操作は、ロックを保持したまま行う。

## 10.4 ウインドウ

ウインドウは、外形、ワークエリア、タイトルバー、スクロールバー、重なり順を持つ。ウインドウの枠とタイトルバーはウインドウマネージャが描き、ワークエリアの中はそのウインドウのプログラムが描く。タイトルバーの左端には、ウインドウが表示している実身のアイコンを表示する。プロセスの小物のウインドウには、そのプログラムの実身のアイコンが表示される。

ウインドウの外観は超漢字Vに合わせてある。角の丸み、半透明のタイトルバー、影、壁紙(並べて表示、中央、拡大)を備える。半透明になるのはタイトルバーだけで、ワークエリアは透過しない。

操作の規則は次のとおりである。

- タイトルバーをドラッグするとウインドウが移動する。右下の角をドラッグするとサイズが変わる。
- タイトルバー左端のピクトグラムをダブルクリックすると、ウインドウを閉じる。
- ウインドウを閉じると、残ったウインドウのうち最前面のものに入力フォーカスが移る。
- ホイールの縦と横の回転は、ポインタの下にあるウインドウのプログラムにイベントとして通知される。
- 右ボタンで、入力フォーカスを持つウインドウのメニューが開く。ウインドウのない場所で押したときは、最前面のウインドウのメニューが開く。メニューが開いている間、ポインタとキーの入力はメニューだけに渡し、下のウインドウやパネルには通知しない。パネルの部品は左ボタンだけで操作し、右ボタンの押下では選択を変えない。
- Shift+Pauseはどのウインドウにも渡さない。ウインドウマネージャが入力を振り分ける`wm_read_event`で受け取り、最前面のウインドウを作ったプロセスを強制終了する(5.5.1)。

ウインドウは実身としても扱える(ウインドウの実身、8.1)。プロセスは`ob_cre_obj`でウインドウを作成し、キーを開き、イベント通知を要求して入力を受け取る。ウインドウの実身のレコードは次のとおりである。

| レコード | 内容 |
| --- | --- |
| 0　描画 | xmlTAD。書き込むとウインドウの内容がそのTADになる |
| 1　形状 | ウインドウの形を表すxmlTADの図形 |
| 2　配置 | 外形、ワークエリア、重なり順、表示の有無。書き込むとウインドウが移動する |
| 3　状態 | 部品の値 |
| 4以降 | ウインドウの種類ごとのデータ。ウインドウではレコード4がドロップされた仮身、レコード5がスクロールバー、パネルではその部品へのリンク、メニューでは項目 |

ウインドウの作成時のメタデータに、`"rect":[左,上,右,下]`、`"attr":枠の種類`、`"shows":"UUID"`(表示している実身)、`"icon":"UUID"`(アイコンを借りる実身)、`"sub":"UUID"`(親のウインドウ)を指定できる。

`"attr"`に右(`WM_ATTR_RBAR`)、下(`WM_ATTR_BBAR`)、左(`WM_ATTR_LBAR`)のスクロールバーを含めると、そのウインドウはスクロールバーを持つ。スクロールバーのレコード(`OB_WR_BARS`)は、右、下、左の順に並んだ`T_OBWBAR`で、それぞれ全体の範囲(`lo`〜`hi`)と、そのうちワークエリアが表示している範囲(`clo`〜`chi`)を持つ。単位はプログラムが決める。プログラムはスクロールするたびにこのレコードを書き、つまみの位置と長さを合わせる。スクロールバーの操作はデスクトップが受け取る。つまみの前後の領域を押すと1画面分、つまみをドラッグするとその位置へのスクロールを、`OB_E_SCROLL`でプログラムに通知する。通知の`code`はどのスクロールバーか(`OB_BAR_*`)、`x`は表示範囲の先頭の移動先(範囲内に収めた値)、`y`は操作の種類(`OB_SCR_PAGE`、ドラッグ中の`OB_SCR_KNOB`、離したときの`OB_SCR_DONE`)である。ドラッグ中の通知は外観設定テーブルの`LK_SCR_LIVE`(ドラッグ中にページを追従させる)が1のときだけ送り、つまみそのものはデスクトップが動かす。スクロールバーの上でのボタンの押下はプログラムにも`OB_E_PRESS`として届くが、位置がワークエリアの外になるので区別できる。

`"sub"`を指定したウインドウは従属ウインドウになる。ウインドウマネージャは、どのウインドウを前面に出したり背面に回したりしても、従属ウインドウを常に親のウインドウのすぐ前に置く(`wm_set_parent`)。親が閉じると、従属ウインドウは独立したウインドウに戻る。タイトルバーのない従属ウインドウも、クリックすると前面に出て入力フォーカスを受け取る。ブラウザのツールパネルがこれを使う(14.7)。

ウインドウはそれを作ったプロセスを記録していて、プロセスが終了するとシステムが閉じる(5.5)。

ウインドウの枠とポインタは、ウインドウマネージャが持つ1つの描画環境を、描くたびにそのウインドウのピクセルか画面に向けて描く。枠を描くのはウインドウを開いたり動かしたりしたタスク(プロセスのタスクのこともある)で、ポインタを描くのは画面を組み立てるタスクである。この描画環境は専用のロックで守り、向け先の設定から描き終わるまでを1つの操作にする。守らないと、ウインドウを開いたプロセスが枠を描いている途中でデスクトップが画面を組み立てたとき、一方の向け先に他方の範囲で描き、ウインドウのピクセルの末尾を越えて書き込む。ロックの順序はウインドウマネージャのロック(`wm_mtxid`)が先である。

試験が画面を写すときは`wm_copy_screen`を使う。ウインドウマネージャの排他の中で画面全体を写すので、画面を組み立て直している途中の状態は写らない。

## 10.5 外観設定テーブル

ウインドウ、部品、パネル、メニューの色、パターン、長さ、時間は、番号付きの外観設定テーブルから取得する。番号は固定で、定義は番号でテーブルの値を参照する。

| 番号 | 内容 |
| --- | --- |
| 250〜319 | 長さと時間(タイトルバーの高さ、スクロールバーの幅、ダブルクリックの間隔、カーソルの点滅) |
| 400〜499 | パターン(背景、縁、タイトルバー、ランプ、スクロールバーのつまみ) |
| 550〜579 | 色 |
| 580〜599 | フォント |
| 9000〜9199 | 設定(キーとポインタの属性、音、入力方式) |

配色は外観設定テーブルの値の組で、システム環境設定で切り替える。ユーザ環境設定で変更する値も、このテーブルの設定項目である。タイトルの文字サイズとスクロールバーの幅を変えると、開いているすべてのウインドウの枠とワークエリアがその場で再計算され、再描画される。メニューの文字サイズは次に開くメニューから反映される。ポインタのサイズを変えたときは、変更前のサイズで元の場所を再描画する。プロセスは`wm_look`で値を読み出し、管理者は`wm_set_look`で書き換えられる。

## 10.6 部品

部品は、BTRONの部品と同じ種類と番号を持つ。

| 番号 | 部品 |
| --- | --- |
| 1 TB | テキストボックス |
| 2 XB | 秘匿テキストボックス(パスワード入力) |
| 3 NB | 数値ボックス |
| 4 SB | 連番ボックス(数値や名前の欄を並べたもの) |
| 5 AS | オン/オフスイッチ |
| 6 MS | 押しボタン |
| 9 WS | スイッチセレクタ |
| 10 SS | スクロールセレクタ |
| 11 VL | ボリューム |
| 13 | タブパネル |
| 0 | ラベル |
| 14 | 線 |

部品の描画と操作は次のとおりである。

- 名前の文字は16ドットで、明るい色の影を右下に1ドットずらして付ける。
- スイッチは角を丸めた立体的な箱で、Enterで押されるスイッチは内側に強調枠を持つ。
- オン/オフスイッチとセレクタの名前の前にはランプがあり、選択したものが点灯する。現在有効な値の名前には下線を引く。
- 押しボタンにランプはない。名前の文字間を広げてボタン全体に描き、押している間は枠を反転表示する。
- スイッチとセレクタは、ボタンを離したときに部品の上にあれば有効になる。押したまま部品の外へ出ればキャンセルできる。
- テキストボックスは、入力フォーカスを持つ間は白背景になり、カーソルが点滅する。Tabで次のボックスに移り、ボックスに入ると文字列全体が選択される。かな漢字変換で日本語を入力できるボックスもある。
- 連番ボックスは欄ごとに数値か名前を持つ。入力中の欄の下の三角を押すか、上下の矢印キーで値が増減する。
- ボリュームはスクロールバーと同じ形で、つまみをドラッグして値を変える。

タブパネルは、上下2段のタブを持つ部品である。各部品は自分が属するタブを持ち、そのタブが選択されているときだけ描画され、操作を受け付ける。

## 10.7 パネルとデータボックス

パネルは部品を並べたものである。パネルの定義は、データボックス実身のレコード0に、番号付きの`<panel>`要素としてxmlTADで書く。

```xml
<databox>
<panel num="1" rect="0,0,435,324" title="ネットワーク設定" kind="bare">
<tags num="100" rect="0,0,435,324" inner="4,28,431,320" value="1">
<tag>＠ネットワーク</tag><tag>アドレス</tag><tag>＋状態</tag>
</tags>
<text sheet="1" x="8" y="80">自ホスト：</text>
<box num="11" sheet="1" rect="136,58,264,88" max="79" ascii="true"/>
<button num="35" sheet="2" rect="320,272,408,296">表示更新</button>
</panel>
</databox>
```

部品の要素には、`text`(ラベル)、`tags`(タブパネル)、`box`(テキストボックス)、`secret`(秘匿テキストボックス)、`number`(数値ボックス)、`serial`(連番ボックス)、`switch`(オン/オフスイッチ)、`button`(押しボタン)、`select`(セレクタ)、`list`(スクロールセレクタ)、`volume`(ボリューム)、`line`(線)がある。ラベルの位置は(x、ベースライン)で指定する。部品はプログラムから`num`の番号で指定する。

プロセスは、パネルの実身を作成するときにメタデータの`tessronos.part`に`box`(データボックスのUUID)と`num`(パネルの番号)を指定し、`ob_map_rec`で自分のウインドウに配置する。パネルのリンクのレコードから部品のUUIDを取得し、部品を開く。部品の値は状態のレコード(3)で読み書きし、セレクタの名前の並びは部品のレコード4に書く。無効状態と非表示状態は配置のレコード(2)のフラグで切り替える。部品で起きたイベントはパネルのその部品のリンクのレコードにも通知されるので、パネルに一度だけ通知を要求すればよい。

`lib/libui`は、この手順と、部品を番号で読み書きする関数をまとめたライブラリである。描画は一切しない。

## 10.8 メニュー

メニューは定義実身から作成する。定義実身のレコード0の`<menu>`要素に項目を並べる。

```xml
<menu>
<include><link id="…_0.xtad"/></include>
<item code="update" key="S">設定を更新</item>
<line/>
<item code="clear">削除</item>
</menu>
```

`<include>`は別の定義の項目をその位置に取り込む。どのウインドウのメニューにも出る共通の項目(閉じる、仮身操作、実身操作、屑実身操作、ウインドウ、小物、実行)はシステムの定義実身にあり、プログラムはそれを取り込むだけでよい。項目にリンクを持たせると、そのリンク先の定義がその項目のサブメニューになる。プログラムのコードが扱うのは定義実身のUUIDと項目の`code`だけで、メニューの文言や並び順はコードに書かない。プロセスは`mn_cre_men`でメニューを作成し、`mn_pop_men`で表示して選択結果を受け取る。

## 10.9 メッセージ行とトレー

画面下端のメッセージ行は、入力モード(英字、日本語、ローマ字、かな)と時刻を表示し、プログラムの短いメッセージを表示する(`wm_msg_put`)。トレーは、プログラム間で仮身や文字列を受け渡すための一時的な保管場所(クリップボード)である。

## 10.10 かな漢字変換

かな漢字変換は、Mozcを移植した変換エンジン(`MOZC=1`でリンクする)で行う。リンクしない構成では、ローマ字からかなへの変換だけを行う。入力モードは[ひらがな/カタカナ]キーで日本語、[英数]キーで英字に切り替わる。デスクトップの文章と図形のウインドウ、パネルのテキストボックス、プロセス(`kc_`のSVC)が、同じ変換エンジンを使う。
