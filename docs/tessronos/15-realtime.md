# 第15章　実時間制御TAD

## 15.1 概要

実時間制御TADは時間に沿って進むデータ(音楽の演奏、アニメーション、映像と音声の再生、字幕)をxmlTADで書いたものである。仕様はTADjs Desktopの「実時間TAD仕様」(`realtimeDataTAD.md`、バージョン2.0)に従う。実身のレコードの中の`<realtime>`要素が1つのプログラムで、その下の`<realData>`が順に実行される実時間データ、`<realGroup>`が時間を共有するイベントの組である。`<realtime>`はレコードのルート(`<tad><realtime>`)にも、文章の中(`<tad><document><realtime>`)にも、図形の中(`<tad><figure><realtime>`)にも置ける。`<realtime>`の直下の`<figure>`は、プログラムが動かす図形、文字枠、画像を置くシーンである。

TessronOSでは、実時間制御TADを次の3つの方法で再生する。

| 方法 | 内容 |
| --- | --- |
| MPEG Player | 実身をMPEG Playerのウインドウで再生する(11.12、15.5.1)。`<realtime>`だけのレコードの実身を開くと、既定でこれが使われる |
| スライド | スライドの1枚が実時間制御TADなら、その場で再生する(11.11)。仮身を持たない`<realtime>`の文章は、それ自身を1枚のスライドとして表示する |
| 二進TAD | 実時間制御のセグメントを二進TADとxmlTADの間で相互に変換する(15.7)。書庫管理とバックアップが使う |

## 15.2 構成

| 部分 | 置き場所 | 動作する場所 | 役割 |
| --- | --- | --- | --- |
| 実行系 | `lib/librtad/`、`include/ts/rtad.h` | 再生するアプリ(プロセス)。カーネルのテストとホストのテストにもリンクする | `<realtime>`を読んでプログラムにし、時刻に従って実行する。描画も入出力もせず、ホストの関数を呼ぶ |
| 再生部 | `lib/librtplay/rtplay.c`、`include/ts/rtplay.h` | 再生するアプリ(プロセス) | シーンを組み、実行系の要求に応じてオブジェクトを動かしてアプリのウインドウに描く。音と映像のプロセスを子として起動し、チャネルでコマンドを送る。プレイリストと背景色変更のパネルを出す(15.5.1) |
| スライド | `application/slide/` | プロセス | スライドの1枚として再生部を持つ(11.11) |
| 実時間メディア | `application/rtmedia/` | プロセス | 音声ファイル(WAVE、MP3)、音符、MIDIメッセージ、PCMをミキシングしてサウンドデバイス`snda`へ出す |
| MPEG Player | `ffmpeg_btron/tessron/mpegplay_ts.c`(別リポジトリ、パッケージ`etc/pkg/mpegplay.tpk`) | プロセス | 実時間制御TADの実身を開くアプリ(11.12)。`--embed`で起動されるとウインドウを持たず、映像をデコードしてメモリ実身へ書き、音声を鳴らす |
| 二進TADの変換 | `lib/libbpk/bpk_rt.c`、`bpk_tad.c`、`lib/libbtbk/btbk_tad.c` | ライブラリ | 実時間制御の要素とセグメントの対応表と、相互の変換 |

実行系と再生部は、再生するアプリのプロセスにリンクする。シーンの描画には文章と図形の表示部(`tv_doc_draw`、`tv_fig_draw`)を使い、表示部はカーネルと同じソースを`TV_USER`でコンパイルしてプロセスにリンクできる(`include/ts/tvport.h`、11.11)。再生部はシーンをプロセスのメモリの描画環境(`dp_open_mem`)に描いてレイヤとスプライトを作り、合成したピクセルを`dp_put_argb`でウインドウに置く。アプリに置くと、再生がデスクトップの都合で止まらず、再生部の異常はそのアプリだけで済み、デスクトップがプロセスのウインドウを借りて描く特別な仕組み(以前の`dtrthost.c`)が要らない。フレームごとのシステムコールは変わった矩形の`dp_put_argb`と`wm_obj_flush`だけである。実行系はシステムコールを呼ばず、メモリの確保と解放もホストの関数で行うので、カーネルのテスト(`tests/ktest/ktest_rt.c`)とホストのテストの両方にそのままリンクしてテストできる。カーネルは浮動小数点のレジスタを使わない(`-mgeneral-regs-only`)ので、実行系は整数だけで計算する。

音と映像は、再生するアプリとも別のプロセスにした。音の合成とデコードは浮動小数点を使い、MP3と映像のデコードは重く、FFmpegは大きさと構成(newlib、POSIXのスレッド)がスライドのような小さなアプリに合わない。プロセスに分けると、デコードの遅れや異常がシーンの動きとアプリの操作を止めない。MPEG Playerは独立したパッケージなので、入っていなければ映像は再生できないが、実行系は`<video>`の`onerror`と`<fallback>`で代わりの処理を行う(15.6.1)。

## 15.3 プログラム(データ構造)

`rt_new`は、`<realtime>`の要素のツリーをノードの列(プログラム)に変換する。ノードは要素ごとに1つで、子を持つ要素(`<realGroup>`、`<if>`、`<while>`、`<random>`、`<interpolate>`、`<keyframes>`、`<trigger>`、`<onerror>`)は、子の範囲の終わりを持つ。読み込む時点で次のものを決める。

| もの | 内容 |
| --- | --- |
| オブジェクト(`RT_OBJ`) | プログラムが`ref`や`id`で指す図形、文字枠(`<text id>`の文章)、画像、映像。位置(左上右下)、不透明度、回転、拡大率、反転、重なり順、表示の有無を持ち、レコードに書かれた値を初期値として残す |
| メディア(`RT_MEDIA`) | `<audio>`と`<video>`。状態(待機、読込み中、準備済み、再生中、一時停止、終了、停止、エラー)、すべての属性、`<fallback>`の並び、リトライの回数を持つ。数に上限はなく、表はメモリの許す限り大きくする |
| ストリーム(`RT_STREAM`) | `<stream>`の番号、`<deviceName>`、`<deviceParams>`、`<streamData>` |
| 単位系 | `<unitSystem>`の主単位と補助単位。時間の値は、そのときの単位系と補助単位、`<unitSpecTemp>`、`<unitScale>`、`<absoluteUnitCoeff>`、要素の`unit`属性(us、ms、s、min、tick)から、マイクロ秒に換算する |
| 式 | `<expr>`を16ビットの逆ポーランド記法のコード列にする。定数は`0x8100`以上、変数はその番号、演算は`0x8000`台(仕様6.2の表)。0での除算の結果は0 |

時刻はマイクロ秒の64ビット整数(`RT_TIME`)、値は100万分の1を単位とする整数(`RT_V`)、イージングの曲線(`function`)は65536分の1で表す。単位系の指定がないときの時間の単位はミリ秒で、`tick`は単位系がなければ960分の1秒とする。変数は符号付き32ビットで、`0x4000`から`0x4007`はシステムの値(プログラムの時刻のミリ秒、乱数、最後に押したキー、ポインタの位置、再生中のメディアの数、スライドの番号、実行中の`<realData>`の番号)である。

## 15.4 実行

実行系は、`rt_step(rt, now)`を呼ばれるたびに`now`までに予定された処理をすべて行い、次に何かをする時刻を返す。何も動いていなければ外からのイベントを待つ(`RT_NEVER`)。滑らかに変わるものがある間は、次のフレーム(60分の1秒、`RT_FRAME_US`)の時刻を返す。

実行の単位はスレッドで、各スレッドは自分の時刻を持つ。`<realData>`は1本のスレッドで始まり、並列のグループ(`type="parallel"`)は親と同じ時刻から新しいスレッドとして子を実行し、親はグループの直後へ進む。直列のグループ(`serial`)では、子の実行が終わった時刻から親が続く。`<timeDelta>`はスレッドの時刻を進め、`<timeAbsolute>`はスレッドの時刻をいちばん内側のグループの開始からの時刻にする(過去に戻る指定は無視する)。同じ時刻に予定されたものは、レコードに書かれた順に実行する。

| 要素 | 実行のしかた |
| --- | --- |
| `<label>`、`<jump>` | ジャンプ先は、自分とその外側の範囲から探し、なければプログラム全体から探す。`start`と`end`は`<realData>`の先頭と終わり。`next_slide`、`prev_slide`はスライドの移動をホストに要求する |
| `onended="jump:L"` | メディアの終わりでLへジャンプする。実行中のスレッドがLに着いたとき、そこへジャンプする予定のメディアや実行中のグループが先に残っていれば、それが終わるまでLで待つ。プレイリスト(仕様の10.5、10.9)の順次再生はこの規則で成り立つ |
| `<if>`、`<while>`、`<assign>` | 式を評価する。スレッドが時刻を進めずにノードを実行し続けるときは、2万回ごとに1ミリ秒進めて止まらないようにする(`RT_SPIN`) |
| `<random>` | 子から1つを選ぶ。`exclude="last"`は直前と同じものを除く。乱数はxorshift32で、`rt_seed`でシードを与えると同じ選び方を繰り返す |
| `<interpolate>` | 2つの子(音符、図形の位置、制御の値)の間を`divisions`で分け、両端を含む`divisions+1`回を実行する。間隔は`timeDelta`の指定による。`timeDelta`がなければ、与えた値から次の値までを1秒で進める(仕様のサンプルの補間はどれも時間を書いておらず、1分割を1フレームにすると、10分割の移動が0.2秒足らずで終わって飛んだように見えるため)。`function`は直線、スプライン(Catmull-Rom)、ease系、`cubic-bezier`。音符は高さ、強さ、長さを補間して順に鳴らす |
| `<keyframes>` | `offset`の百分率の位置の値の間を、キーごとの`function`で補間する。`iterations`、`direction`、`fill`、`delay`に従う |
| 制御(`audioControl`ほか) | メディアの再生、停止、音量、位置、オブジェクトの位置、不透明度、回転、拡大率、表示、画像の差し替え、文字枠の内容。`duration`があれば、その時間をかけて変える |
| `<wait>` | クリック、キー、時間、メディアの終わりなどを待つ。待っている間、スレッドは進まない |
| `<trigger>` | 入力(click、dblclick、keydown、keyup、mouseenter、mouseleave、swipe、resize、visibility)で子を実行する。`once`、`enabled`、`<triggerControl>`で有効と無効を切り替える |
| `<groupControl>` | 名前で指したグループのスレッドに対して、一時停止、再開、停止、最初から、速度の変更、位置の移動を行う。逆再生はアニメーションだけに働く |
| `<onerror>`、`<fallback>` | メディアのエラー(見つからない、デコードできない、タイムアウト)で代わりの資源を試し、`retry`の回数だけ`retryDelay`後に読み直し、最後に`<onerror>`の子を実行する。`<realData>`の直下の`<onerror>`はプログラム全体の既定である |

`autoplay="false"`の`<realtime>`や`<realData>`はシーンを表示して待ち、利用者が再生を始めると(`rt_begin`)実行する。`<realData>`はレコードに書かれた順に1つずつ実行し、`startDelay`、`loop`、`loopCount`に従う。音符が鳴り終わるまでは、その`<realData>`は終わらない。

一時停止(`rt_pause`)はプログラムの時刻を止め、再開で続きから進める。位置の移動(`rt_seek`)はプログラムを最初から実行し直し、指定の時刻まで音を出さずに早送りする。早送りの間に始まるはずだったメディアは、その時刻からの位置で再生を始める。最初の`<interpolate>`と、`fill="backwards"`のキーフレームの最初の値は、シーンが最初から正しい状態で見えるように、実行の前にオブジェクトへ与える。

## 15.5 再生部

再生部(`rtp_open`)はレコードのシーンを表示部で一度組み、アプリのウインドウの作業領域の中の矩形に収める。シーンの大きさは`<realtime>`の`<figure>`の`<figView>`、なければ1920×1080(スライドはスライドが作られた画面の大きさ)で、矩形に収まる最大の倍率で中央に置く。矩形の残りはシーンの周りの色で塗る。

プログラムが動かさないオブジェクトは、重なり順に従って何枚かのレイヤに描いておき、動かすオブジェクト(図形、文字枠、画像、映像)はそれぞれ1枚のスプライトに描く。スプライトは黒の背景と白の背景に2回描き、2枚の差からその点の不透明度を求める。スプライトはシーンの座標ではなく自分の範囲の左上を原点にした描画領域に描く。シーンの外から滑り込むオブジェクト(左端が負の位置から始まる画像など)も、シーンの範囲で切られずに描ける。再生を始めたときは、オブジェクトを最初の値(フェードで現れるオブジェクトは不透明度0)にしてからシーン全体を描き直す。こうすると文字の縁の中間の色も、下のオブジェクトの上に正しく重なる。フレームごとに、変わった所(前の位置と新しい位置)だけ、レイヤとスプライトを重なり順に、移動、回転、拡大、反転、不透明度を付けて合成し、ウインドウに書いて`wm_obj_flush`で画面に出す。合成は、アプリのメインタスクを止めないよう再生部のタスクが行う。このタスクはアプリのメインタスクと同じ優先度(そのプロセスが持てる最も高いもの)で、プログラムの次のイベントの時刻と、動くオブジェクトがある間はフレームごとにウェイクアップする。POSIXのスレッドを使うアプリ(MPEG Player)は、C言語の実行時ライブラリのロックのため、タスクをスレッドとして作る関数を渡す(`RTP_OPEN`の`spawn`)。newlibだけのアプリ(スライド)は、`lib/librtplay/rtp_mlock.c`をリンクして、`malloc`を一度に1つのタスクだけが呼ぶようにする。再生部の状態は再生部のロック(1つのセマフォ)で保護する。

映像は、そのスプライトにMPEG Playerが書いたフレームを置く。`<video>`の矩形(画面の倍率をかけた大きさ、1280×720まで)をMPEG Playerに伝え、MPEG Playerはその大きさの中央に縦横比を保ってフレームを作る。ポスター(`poster`)は再生が始まるまで表示する。

利用者の操作はシーンの座標に変換して実行系に渡す(`rt_input`)。クリックはその位置のオブジェクトの`<trigger>`と`<wait event="click">`に、キーは`keydown`と`keyup`の名前(`Space`、`ArrowLeft`、`Enter`、`a`など)に渡り、押したまま60単位以上動かして離すとスワイプになる。実行系が受け取らなかった操作は、スライドやMPEG Playerの操作として扱う。

### 15.5.1 アプリのウインドウでの再生

MPEG Playerとスライドは、実時間制御TADの実身を(MPEG Playerはプレイリストの曲として再生するときも)、自分のウインドウで再生部を開いて再生する(`rtp_open`)。開くときに、ウインドウの描画環境、ウインドウのキー、ウインドウのチャネル(パネルの通知が来る所)、シーンを置く矩形(作業領域の左上から)、シーンの周りの色、シーンの背景色(`TAD_COL_NONE`なら実身の背景色、なければ黒)を渡す。スライドとして開くと(`slide`)、スライドが作られた画面の大きさとスライドの番号を渡し、プログラムが要求したスライドの移動(`slide:next`など)を状態の`RTP_S_GO`で返す。MPEG Playerは映像の領域を描かず、下の帯だけを描く。

その後の操作は`rtp_do`で、何をするか(`RTP_*`)と2つの数を渡す。

| `RTP_*` | すること |
| --- | --- |
| `STATE` | 何もせず、状態だけを返す |
| `TOGGLE`、`STOP`、`RESTART` | 再生と一時停止(待っているプログラムは始める)、停止、先頭から |
| `SEEK`、`TRACK` | 1つ目の数のミリ秒進める(負なら戻す)、プレイリストの1つ目の数だけ先(前)の曲へ |
| `AREA`、`REDRAW`、`GROUND` | 2つの数の大きさにシーンを置き直す、周りとシーンを描き直す、背景色変更のパネル |
| `LIST` | プレイリスト表示のパネル。選んだものを再生する |
| `PRESS`、`RELEASE`、`KEY` | 作業領域の2つの数の位置での左ボタンの押下と解放、キー(1つ目の数)。`RTP_KEY_MINE`を付けたキーは、プログラムが受け取るときだけ渡す |
| `MOVE` | ポインタが作業領域の2つの数の位置にある(シーンの外の座標なら、シーンから出た)。`mouseenter`と`mouseleave`のため。MPEG Playerは40ミリ秒に1回まで送る |

状態(`RTP_HOW`)は、`flags`に`RTP_S_PLAYING`、`PAUSED`、`WAITING`、`DONE`、受け取ったときの`TAKEN`、スライドの移動の`GO`(`go`に`RT_ACT_NEXT`、`RT_ACT_PREV`、`RT_ACT_INDEX`、`go_n`にスライドの番号)、パネルを出している間にウインドウが閉じられたときの`CLOSED`、`ms`にプログラムの時刻(ミリ秒)、`media`にプレイリストの数、`now`に再生しているメディアのタイトルとアーティストである。MPEG Playerは250ミリ秒ごとに、スライドは0.1秒ごとに`STATE`で状態を問い合わせる。MPEG Playerは`DONE`をリピートの設定に従って扱う。

プレイリスト表示と背景色変更は、システムのデータボックス「実時間制御TADの再生のデータボックス」(`SYSDEF_BOX_RTPLAY`)のパネルを、アプリのウインドウのチャネルで待って出す。BTRONの部品の一覧と〈取消〉〈了解〉だけのパネルである。

`rtp_close`で閉じると、再生部のタスクを止め、音と映像のプロセスに終了を指示し、チャネルとメモリ実身を消す。アプリが強制終了などで閉じずに終わったときは、音と映像のプロセスが自分で終わる(15.6)。コンソールには、開くと`player: hosted 番号 in a window of process 番号`、操作ごとに`player: 番号 op 名前`、閉じると`player: 番号 closed by its process`を出力する。

R1.300までは再生部をデスクトップ(カーネル)に置き、MPEG Playerとスライドはデスクトップへのリクエスト(`DT_RQ_RT_OPEN`、`DT_RQ_RT_DO`、`DT_RQ_RT_CLOSE`、`dtrthost.c`)で、自分のウインドウでの再生を要求していた。表示部をプロセスにリンクできるようになったので、再生部をアプリの中に移し、リクエストの31から33は使わないことにした。

文章の中の実時間制御TADを、文章のウインドウの一部でその場で再生する仕組みは、今はない(基本文章編集は`<realtime>`を再生せず、文章として表示する)。作るときは、文章のアプリのプロセスが再生部をリンクし、`rtp_open`の矩形に文章の中のシーンの位置を渡して、アプリの中で再生する。デスクトップに戻さないのは、上と同じ理由である。

## 15.6 メディアの経路

再生部は音と映像を処理するプロセスを、プログラム実身から`ob_cre_obj`で、再生するアプリの子として起動する。チャネルとメモリ実身はアプリが作り、アプリの利用者が所有する。引数(`RTM_ARG`、`include/ts/rtmedia.h`)は、コマンドを書くチャネル、応答を読むチャネル、映像ならフレームを置くメモリ実身、再生するアプリのプロセスの実身のUUIDである。音と映像のプロセスは、アプリのプロセスの実身の終了(`OB_E_EXIT`)をコマンドのチャネルに通知するよう要求する(番号`RTM_HOST_ID`)。アプリが強制終了などで閉じずに終わると、その通知で、受け取ったチャネルとメモリ実身を消して自分も終わる(`rtmedia: the program it played for has ended`、`mpegplay: embedded: the program it played for has ended`)。子のプロセスは親が終わっても終わらない(5.5.7)ので、こうしないと音が鳴り続ける。コマンド(`RTM_CMD`)は資源を開く、再生、一時停止、再開、停止、位置、音量、定位、速度、ミュート、閉じる、音符、MIDI、ストリーム、PCM、すべての音とメディアの停止、大きさ、終了で、応答(`RTM_A_*`)は読込み完了(長さと映像の大きさ)、再生中、一時停止、終了、エラー、位置、フレーム、起動完了である。資源は、`{realId}_0_1.mp3`のように実身の資源の名前で、または取り込んだファイルの実身のレコードで指す。

時刻はモノトニッククロックのナノ秒で渡す。実時間メディアはすべての音をコマンドの時刻から一定の80ミリ秒後に鳴らすので、2つの音の間隔はプログラムのとおりになる。映像も同じ遅れで表示されるので、音と映像は同期する。音のプログラムがあるときは、実時間メディアが起動完了を返すまで(最大3秒)、プログラムの開始を待つ。

### 15.6.1 映像

映像はMPEG Player(`mpeg-player`)を`--embed`で起動して再生する。起動されたMPEG Playerはウインドウを作らず、コマンドのチャネルを読み、資源を開いて長さと大きさを返し、再生のコマンドでFFmpegのデコードを始める。音声はMPEG Player自身が`snda`へ出し、フレームはメモリ実身のレコード0の2つのフレームの領域に交互に書き、ヘッダ(`RTM_FRAMES`)で書いた方を指して、応答のチャネルで通知する。WAVEとMP3以外の音声ファイル(AAC、Ogg、FLACなど)も、MPEG Playerで再生する。`<video>`1つにつき1つのMPEG Playerが動く。

MPEG Playerのパッケージが入っていなければ、映像と、実時間メディアがデコードできない形式の音声は、資源を開いた時点で「対応しない形式」のエラーになる。`<fallback condition="unsupported">`があればそれを試し、なければ`<onerror>`を実行する。メディアの`onended`で次へ進むプログラムは、エラーでも次へ進む。

### 15.6.2 実時間メディア

実時間メディア(`application/rtmedia/`、プログラム実身のレコード1)は、3つのタスクを持つ。メインタスクがコマンドを読み、読込みタスクが資源を読んで48kHz、ステレオ、16ビットにデコードし(WAVEは8、16、24、32ビットと浮動小数点、MP3はminimp3)、ミキシングのタスクが5ミリ秒ずつ音を作って`snda`へ書く。音量、定位、速度、ループ区間、フェードイン、フェードアウトはミキシングのタスクが処理する。

### 15.6.3 音源

MIDIの機器はないので、音符とMIDIメッセージはすべてソフトウェアで合成する。General MIDIの音色の系統ごとに合成方法を決めてあり、ピアノ、ベース、ベルは減衰する倍音、オルガン、弦、金管、リード、フルートは持続する倍音、ギターは撥弦音(ディレイラインの平均)、チャネル10のドラムは周波数を下げるサイン波(バスドラム、タム)とフィルタを通したノイズ(スネア、シンバル)である。ストリームの`<deviceName>`が`inst:Piano`のような名前なら、その音色で鳴らす。`synthX:`は`<deviceParams>`の波形(sine、square、saw、triangle、noise)とエンベロープで鳴らす。MIDIメッセージはノートオン、ノートオフ、プログラムチェンジ、コントロールチェンジ(音量、パン、サステイン、全音停止)、ピッチベンドを解釈する。

## 15.7 二進TAD

実時間制御の要素は仕様11章のセグメントIDとSUBIDの二進TADになる(`TS_RGRP`は`0xFFD0`、`TS_REAL`は`0xFFEA`のように、表の値に`0xFF00`を加えたもの)。セグメントの本体の形式は仕様にないので、TessronOSでは次のように決めた。

| 位置 | 内容 |
| --- | --- |
| 最初のワード | SUBID×256+フラグ。フラグ1は、要素の中の要素が後に続き、終わりのセグメントで閉じることを示す |
| 名前 | SUBIDを持たない要素(`<then>`、`<expr>`、`<deviceName>`など)だけ。`TS_REAL`のSUBID `0x10`で、16ビットの長さと名前 |
| 属性 | 16ビットの数、続いて属性ごとに16ビットの長さと名前、32ビットの長さと値。文字列はUTF-8で実体参照を戻し、奇数の長さには1バイトのパディングを入れる。要素の文字は名前が空の属性 |

SUBIDの表で終わりを持つ要素(`<realGroup>`、`<if>`、`<while>`、`<random>`、`<interpolate>`、`<keyframes>`、`<trigger>`、`<onerror>`、`<realData>`)は表の終わりのSUBIDで、それ以外は`TS_REAL`のSUBID `0x11`で閉じる。仕様の表に`<realtime>`、`<stream>`、`<eventArray>`、`<else>`、`<figureRef>`の番号はないので、`TS_REAL`のSUBID 2と`TS_REALEND`のSUBID 2を`<realtime>`に、`TS_REAL`のSUBID 1を`<stream>`に、`TS_RGRP`のSUBID 4と5を`<eventArray>`に、`TS_BRLP`のSUBID 10を`<else>`に、`TS_MEDIA`のSUBID 4を`<figureRef>`に割り当てた。要素の間の文字は`TS_REAL`のSUBID `0x12`である。

`TS_MEDIA`(`0xFFA0`、ソースでは`TS_RMEDIA`)と`TS_MCTL`(`0xFFB0`、`TS_RMCTL`)は、文章のページ割付け(`TS_TPAGE`)と図形要素(`TS_FPRIM`)と同じ番号なので、実時間制御の要素のすぐ内側にあるときだけメディアとメディア制御として解釈する。プログラムが図形や文字枠を指す`id`属性は二進TADの図形要素にないので、`id`を持つ図形、画像、文字枠、`<text>`の直後に`TS_REAL`のSUBID `0x13`(要素の名前とid)を置き、xmlTADに戻すときに直前のその要素へ`id`を付け直す。文章の中の`<realtime>`は段落の間に置く。xmlTADから二進TADへ、二進TADからxmlTADへと変換したものは、もう一度変換しても同じバイト列になる。

## 15.8 仕様への対応

| 仕様の章 | 対応 |

| 2 ルート要素の属性 | `autoplay`、`preload`、`loop`(全体の繰り返し)。`preload="none"`の資源は再生の直前に読む |
| 3 `<realData>`、`<stream>`、デバイス名、複数のブロック | すべて。デバイス名は`inst:`、`MIDIn:`、`synthX:`、`audio:`、`display:`を解釈する |
| 4 `<realGroup>`、入れ子、`<eventArray>` | すべて。`<eventArray>`の中のイベントは、それが置かれたスレッドでその場で順に実行する |
| 5 `<timeDelta>`、`<timeAbsolute>` | すべて |
| 6 式、`<label>`、`<jump>`、`<if>`、`<while>`、`<assign>`、`<random>` | すべて。式の演算は6.2の表のすべて |
| 7 `<interpolate>` | 音符、図形の位置(`<figureRef>`)、制御の値。MIDIメッセージの補間はしない(両端の値をそのまま送る) |
| 8 単位系 | すべて |
| 9.1〜9.4 音符、MIDI、PCM | すべて。音源はソフトウェアの合成(15.6.3) |
| 9.5〜9.7 `<audio>`、`<video>`、`<image>` | すべての属性。映像はMPEG Playerがあるとき。メタデータ(`title`、`artist`、`album`、`trackNumber`)はプレイリストに表示する |
| 9.8〜9.12 制御 | すべての命令。`playbackRate`は音声だけで、映像は1倍のまま |
| 9.13 `<wait>` | すべてのイベント |
| 9.14 `<keyframes>` | すべて |
| 9.15 `<trigger>`、`<triggerControl>` | すべてのイベント。`visibility`はウインドウの表示と非表示、`resize`はウインドウの大きさの変化 |
| 9.16 `<onerror>`、`<fallback>` | すべて。`condition="slow"`は、ネットワークから資源を取得しないので当てはまらない |
| 9.17 `<groupControl>` | すべて。`reverse`はアニメーションだけを逆に進める |
| 10 使用例 | 10.1〜10.9のすべてを、サンプルの実身「実時間TAD見本」で再生できる(15.10) |

## 15.9 制限

音と映像の遅れは一定の80ミリ秒と見なしており、機器ごとの実際の遅れは測らない。映像は1つの`<video>`につき1つのプロセスで、同時にいくつも再生すると重い。フレームは1280×720までの大きさで作り、それより大きく表示するときは拡大する。位置の移動は最初から実行し直すので、長いプログラムでは時間がかかる。MIDIの外部機器、`<streamData>`による音色の読込み、インターネット上の資源(`http:`)には対応しない。

## 15.10 テスト

カーネルのテストの`rt`グループ(`tests/ktest/ktest_rt.c`)は、実行系をテスト用の時計で1ミリ秒ずつ進め、数値と名前の変換、要素の読込み、式、分岐と繰り返しとラベル、単位系、補間、シードを与えた`<random>`、メディアの読込みとエラーと代替、トリガー、待機、キーフレーム、一時停止と位置の移動、スライドの移動の要求を、鳴った音と要求された操作の時刻で確認する。メディアは5ミリ秒で読み込めて3秒で終わるものとし、名前に「missing」を含むものは見つからないことにする。続いて同じレコードを二進TADにし、xmlTADに戻し、もう一度二進TADにして同じバイト列になること、戻したレコードが元と同じに実行されることを確認する。

サンプルの実身「実時間TAD見本」(仮身サンプルの中、`etc/xtad/01a0d8c5-6a00-*`)は、仕様10章の9つの例を1枚ずつのスライドにしたもので、例ごとの実身(`01a0d8c5-6a01-*`から`6a09-*`)は音声(MP3)、映像(H.264とAACのMP4)、画像(PNG、JPEG)の資源を持つ。画面は、サンプルを順に再生する`tools/tests/ui_rt.steps`と、MPEG Playerのウインドウでの再生、操作、大きさの変更、仮身の「実行」を確認する`tools/tests/ui_rt_player.steps`を`tools/ui_run.py`で実行して確認する(12.4)。カーネルのテストの`dtwin`グループの`test_player`は、サンプルをMPEG Playerで開き、クリックとポインタの移動がプログラムに渡ること、Spaceで再生と一時停止が切り替わること、大きさを変えるとシーンを置き直すこと、Ctrl+Eで閉じたときとプロセスを終わらせたときに再生部が閉じることを確認する。`--wav`を付けると鳴った音をWAVEファイルで確認でき、プレイリストの曲の周波数とMPEG Playerの映像の音が記録される。また、`tools/tests/test_bpk.py`と`test_btbackup.py`は、二進TADの変換を表とともにホストでビルドしてテストする。
