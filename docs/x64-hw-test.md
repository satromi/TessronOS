# x64の実機で試す手順

ThinkPad X1 Yoga(第3世代)とMicrosoft Surface Go 2で、TessronOSのx64のイメージをUSBから起動して試す手順です。TessronOSは起動したUSBの記憶装置にだけ書き込み、内蔵のSSD(Windows)には書き込みません。

## 1. 用意するもの

- イメージ: `C:\home\TessronOS\build_make\obj\_X64_hw2\sd.img`(1,948,254,208バイト)
  - sha256: `b96fbf23386f5b644747a5586c02a9a5289ee0caf48d4310cc1b94afac30df99`
  - 作り直すときは`C:\tmp\mkimg_x64hw2.cmd`を実行します(ログは`C:\tmp\mkimg_x64hw2.log`)。作り直すとsha256は変わります。
- 1GB以上のUSBメモリか、USBのアダプタに挿したSDカード。中身はすべて消えます。
- USBのキーボードとマウス(X1 Yogaで内蔵のキーボードが動かないときのため)。
- あれば、USBの有線LANのアダプタ(RTL8153系)と、X1 Yoga用の専用のEthernetの拡張アダプタ。
- 画面の写真を撮るカメラ(スマートフォンでよい)。

### OpenBSDの層のイメージ

6章の16.(Wi-FiのOpenBSDの802.11の層、設計書9.6.9)は、既定のイメージ(hw2)では試せません。hw2と同じ構成(ブラウザ入り)に`WIFI_NET80211=obsd`を足し、BUILD_IDを分けて(例`hw2o`)別に作ります。hw2の置き場は変わりません。

1. `C:\tmp\mkimg_x64hw2.sh`を`C:\tmp\mkimg_x64hw2o.sh`に写し、次の4か所を変えます。`LOG=/mnt/c/tmp/mkimg_x64hw2o.log`、`rm -rf obj/_X64_hw2o`、make の指定に`WIFI_NET80211=obsd`を足して`BUILD_ID=hw2o`にする、あとの`obj/_X64_hw2`を`obj/_X64_hw2o`にする。make の指定は次のとおりです。

   ```text
   make -j4 TARGET=_X64_ DESKTOP=1 MOZC=1 GL=1 WIFI=1 WIFI_NET80211=obsd BROWSER=1 BROWSER_BLINK=1 BUILD_ID=hw2o X64_CMDLINE= sdimg
   ```

2. `C:\tmp\mkimg_x64hw2.cmd`を`mkimg_x64hw2o.cmd`に写し、`mkimg_x64hw2.sh`を`mkimg_x64hw2o.sh`に替えて実行します。初めてのときは、OpenBSD 8.0の`sys.tar.gz`(約69MB)と版36のファームウェアを取得し、`~/tessronos-obsd-x64/obsdwifi.o`を作るので、hw2より数分長くかかります。
3. できたイメージは`C:\home\TessronOS\build_make\obj\_X64_hw2o\sd.img`です。3章の手順で書きます。起動の`KERNEL.TXT`に`iwm0: hw rev ..., fw ver 36...`が出ていれば、OpenBSDの層で動いています(既定のイメージでは`fw ver 22...`)。

## 2. 前もって行うこと(両方の機種)

1. Windowsで、デバイスの暗号化(BitLocker)を使っているかを確かめます。設定の「プライバシーとセキュリティ」の「デバイスの暗号化」か、コントロールパネルの「BitLockerドライブ暗号化」で見られます。
2. 使っているときは、回復キーを控えておきます。Microsoftのアカウントのページ(https://account.microsoft.com/devices/recoverykey)で見られます。「保護の一時停止」で一時停止しておく方法もあります。Secure Bootの設定を変えると、次にWindowsを起動したときに回復キーを求められることがあります。

## 3. USBの記憶装置に書く

Windowsで、次のどちらかで書きます。

- Raspberry Pi Imager: 「OS」で「カスタムイメージを使う」を選んで`sd.img`を指定し、「ストレージ」で書き込み先を選んで書きます。OSの設定の変更(ユーザ名やWi-Fiの設定)は使いません。
- Rufus: 「デバイス」で書き込み先を選び、「ブートの種類」の「選択」で`sd.img`を選んで「スタート」を押します。書き込みの方式を聞かれたら「DDイメージモード」を選びます。

書き込み先を間違えないよう、ドライブの名前と大きさを確かめてから書きます。

## 4. ThinkPad X1 Yoga(第3世代)で起動する

1. 電源を入れ、Lenovoのロゴが出ている間にF1を押してBIOSの設定(ThinkPad Setup)に入ります。
2. 「Security」の「Secure Boot」で「Secure Boot」を「Disabled」にします。
3. 「Startup」の「UEFI/Legacy Boot」が「UEFI Only」か「Both」であることを確かめます。
4. 「Config」の「USB」で「USB UEFI BIOS Support」が「Enabled」であることを確かめます。
5. F10で保存して抜けます。Windowsが起動したら、シャットダウンします。
6. USBの記憶装置、USBのキーボードとマウス、あればLANのアダプタをつなぎます。
7. 電源を入れ、ロゴが出ている間にF12を押して、起動するデバイスの一覧からUSBの記憶装置を選びます。

画面は、何も指定しなければ1600×1200のモードで表示します(ローダがSMBIOSで機種を見分けて選びます)。パネルの2560×1440で試すときは、5章の`cmdline.txt`に`video=2560x1440`と書きます。

## 5. Surface Go 2で起動する

1. 電源を切ります。音量の上げるボタンを押したまま電源ボタンを押して離し、Surfaceのロゴが出たら音量のボタンを離すと、Surface UEFIの画面になります。
2. 「Security」の「Secure Boot」を無効にします(「Disabled」、または構成の選択で「None」)。
3. 「Boot configuration」で「USB Storage」が有効であることを確かめます。
4. 「Exit」の「Restart now」で抜けます。Windowsが起動したら、シャットダウンします。
5. USBの記憶装置、Type Cover、あればUSBのLANのアダプタをつなぎます。USB-Cの変換やハブを使ってもかまいません。
6. 音量の下げるボタンを押したまま電源ボタンを押して離し、ロゴが出たら音量のボタンを離すと、USBの記憶装置から起動します。

## 6. 確かめること

### 両方の機種

- デスクトップまで起動するか。止まったら7章の手順で記録を残します。
- USB: USBメモリ、キーボード、マウスを、本体の口とハブの両方で抜き差しし、デスクトップに仮身が出入りするか。
- 電池: デバイス箱の`battery0`と`acpower`の実身を開き、レコード1の値を写真に撮ります。ACアダプタを抜き差しして、値が変わるかを見ます。
- 音: PCM Playerで音を鳴らし、音量を変えられるか。
- 電源ボタン: 押して電源が切れるか。
- 起動できたときも、デスクトップで1分以上待ってから電源を切り、7章の手順で記録を持ち帰ります。

### ThinkPad X1 Yoga

- 内蔵のキーボードとTrackPointが動くか(デバイス箱の`ps2kbd`と`ps2aux`)。
- USBは確かめ済みです(2026-10-19)。チップセットのxHCIで、本体の口とハブの先の装置がシステム環境設定のUSBの一覧に出ました。内蔵のカメラ、Bluetooth、指紋センサ、Wacomのペンとタッチも、本来の速さでつながります。Type-Cの口(Thunderbolt 3のコントローラ)は、まだ確かめていません。
- 何も指定しないときに1600×1200で表示されるか(写真)。`LOADER.TXT`に「1600x1200, the mode this machine is given」と出ます。
- 解像度の変更(再起動しません)。システム環境設定の〈機器〉〈機器情報〉で「画面サイズ／色数」を選び〈表示〉を押します。次の順に、大きさを一覧から選ぶか「幅×高さ」の欄に入れ、「比の違う大きさ」を選んで〈設定〉を押します。そのたびに画面の写真を撮り、確認のパネルで［Ｅｎｔｅｒ］を押して残します。
  1. 2560×1440(パネルの本来の大きさ。文字が小さくなります)
  2. 1920×1080(パネルと同じ16:9なので、ゆがまずに全体に出るはずです)
  3. 1600×1200と「比を保つ」(左右に黒い帯が出るはずです)
  4. 1600×1200と「全体に広げる」(横に伸びるはずです)
  5. 幅と高さを手で入れた大きさ(例: 1700×1000)
  6. 1920×1080を選び、確認のパネルで何も押さずに30秒待つ(前の大きさに戻るはずです)
  - 画面が崩れたり黒くなったりしたときは、何も押さずに30秒待つと前の大きさに戻ります。戻らなければ、電源ボタンを長く押して切り、記録を持ち帰ります。残した大きさは次の起動でも使われます。
  - 終わったら1分以上待ってから電源を切り、7章の手順で記録を持ち帰ります。変更の手順の記録は`DISPLAY.TXT`の最後の節と`KERNEL.TXT`にあります(変更の2秒後にも書き直します)。
  - 起動時の`KERNEL.TXT`に`igfx: places at GGTT ...`と`igfx: the size can be changed while the system runs`が出ていれば、解像度を変えられる状態です。`igt: the firmware's entries:`の行には、ファームウェアが残したGGTTの項の数と、残した範囲が出ます。描画のGPUは、起動の35秒ほど後に`igt: ready`か`igt: the GPU is NOT used (エラー)`が出ます。
- `video=2560x1440`のときに2560×1440で表示されるか(写真)。
- 内蔵のSSDがSATAのモデルなら、デバイスの一覧に`sataa`が出るか(読むだけで、書き込みません)。
- 有線LAN: 専用の拡張アダプタをつなぎ、DHCPでアドレスが取れるか。アダプタが無くても、初期化の記録は残ります。
- 割込みの方式(MSI)。チップセットのxHCI(8086:9d2f)、ThunderboltのxHCI(8086:15d4)、有線LANのI219(8086:15d7)はMSIだけを持ちます。前のイメージでは割込みが取れず、ポーリングで動いていました(`no MSI-X message (-9), MSI capability there: polled`)。
  1. 起動して、デスクトップで1分以上待ちます。USBのマウスを動かし、USBメモリを抜き差しします。有線の拡張アダプタがあれば、つないでケーブルを挿し、ブラウザでページを開きます。Type-Cの口(Thunderbolt)にUSBメモリかハブがあれば挿します。
  2. 7章の手順で`KERNEL.TXT`を持ち帰ります。次の行を見ます。
     - `pcie: 00:14.0 8086:9d2f: interrupt by MSI (番号); MSI-X -9, MSI 0`。`8086:15d7`(e1k)と`8086:15d4`の行も同じく`interrupt by MSI`になるはずです。`INTx`か`polled`なら、行の後ろの`line:`に理由が出ます。
     - `usb: controller 0: 1 interrupts arrived (MSI, interrupt 番号, PRC 1)`と、その後の`10`、`100`、`1000`の行。数が増えていれば割込みが届いています。
     - 有線LANをつないだときは、`e1k: interrupt by MSI`と`e1k: 1 interrupts arrived (MSI, ...)`の行。
     - `no interrupt arrived in 10 s`の行が出たら、その装置の割込みは届いていません(メッセージがどこかで止まっています)。その行と、同じ起動の`pcie: bridge`、`vtd:`の行を持ち帰ります。
  3. マウスやUSBメモリが前と同じに動くか、遅れや取りこぼしが無いかを見ます。
  4. デバイス箱の`neta`の実身で割込みの受け先(`irq.cpu`)を変えたとき、有線LANが続けて使えるかを見ます。
- 蓋を閉じて開いたときに、`lid`の実身が変わるか。
- Wacomのペンとタッチ、ThinkPadのホットキーは、まだ対応していないので動きません。
- Wi-Fi(Intel Dual Band Wireless-AC 8265)。イメージは2026-10-19の夜以降に作ったもの(Wi-Fiを既定で含みます)を使います。手元のアクセスポイントのSSIDとパスワード(WPA2-Personal)を用意します。WPA3だけの設定のアクセスポイントにはつながりません(WPA2とWPA3の両方を受け付ける設定ならWPA2でつながります)。
  1. 起動したら1分待ち、デバイス箱に`wlan0`の実身があるかを見ます。システム環境設定の〈機器〉〈機器情報〉で〈ネットワークアダプタ〉を選び、〈表示〉を押して、アダプタの一覧に「Ｗｉ－Ｆｉ　Intel Wi-Fi 8086:24fd」が出るかを写真に撮ります。
  2. ネットワーク設定を開き、〈Ｗｉ－Ｆｉ〉のタブで〈走査〉を押し、一覧に周りのネットワークが出るかを写真に撮ります。
  3. 一覧から手元のアクセスポイントを選び(SSIDとセキュリティが入ります)、パスワードを入れて〈接続〉を押します。管理者のパスワードを尋ねられたら入れます(初めてのときは決めます)。
  4. 「Ｗｉ－Ｆｉ」の欄が「接続中「SSID」」になるか、〈状態〉のタブに周波数、電波の強さ、速度が出るかを写真に撮ります。有線のLANをつないでいなければ、自動の選択でWi-Fiが使われ、ネットワーク設定の〈ネットワーク〉〈状態〉にDHCPのアドレスが出るはずです。
  5. ブラウザか、ファイル変換のFTPで外につながるかを見ます。時刻が合っているか(SNTP)も見ます。
  6. わざと違うパスワードで〈接続〉を押し、「パスワードが違う可能性があります」と出るかを見ます。その後、正しいパスワードで接続し直します。
  7. 〈切断〉を押して切れるか、〈接続〉でつなぎ直せるかを見ます。
  8. 再起動して、何もしなくても保存したネットワークにつながるかを見ます。
  9. 有線の拡張アダプタがあれば、つないでケーブルを挿し、自動の選択で有線に移るか(`net: adapter wifi -> e1k`)、抜くとWi-Fiに戻るかを見ます。システム環境設定の〈ネットワークアダプタ〉のアダプタの一覧でWi-Fiの行を選んで〈設定〉を押すと、有線をつないだままWi-Fiを使うかも見ます。移るたびに`net: another adapter: the address is asked for again (DHCP)`の行が出て、ネットワーク設定の〈状態〉のアドレスがそのアダプタのものになるかを見ます。
  10. 通信を続けます。つないだまま3分以上、ブラウザでページを開き直したりして使います。`KERNEL.TXT`に1分ごとの`wifi: link:`の行(電波の強さ、速さ、送った数、受けた数、捨てた数)が出ます。速さは54Mb/sまでです。
  11. つなぎ直し。アクセスポイントの電源を切り、30秒待ってから入れます。切れると`wifi: the network was lost`の行が出て、アクセスポイントが戻ると自分からつなぎ直し、`net: the Wi-Fi joined a network: the address is asked for again (DHCP)`の行が出るかを見ます。アクセスポイントの電源を切れないときは、アクセスポイントの管理画面でこのPCを切断させても同じです(そのときは`recv deauthenticate (reason N)`の行に理由が出ます)。
  12. ローミング。同じSSIDのアクセスポイントが2台あるとき(例えばtron2)、つないだ方のアクセスポイントの電源を切るか、PCを持ってもう1台の近くへ移ります。もう1台につなぎ直すか(`wifi: joining "SSID" at <BSSID>`のBSSIDが変わるか)を見ます。電波の弱い所まで動いて、切れた後に戻ったときにつなぎ直すかも見ます。つないでいる間に、より強い方へ自分から移ることはしません。
  13. 〈切断〉と〈接続〉を3回続けて繰り返し、毎回つながるかを見ます。
  14. 始め直し。カードが止まったとき(ファームウェアの誤りなど)は、`wifi: the card stopped`の行が出て、自分でカードを始め直します。わざと起こす方法はありませんが、この行が出ていたら、その前後の行(`iwm0: fatal firmware error`、ファームウェアの誤りの記録)と、その後につながったかを見ます。
  15. Raspberry Pi 5でも試すときは、Pi 5を先に起動してからアクセスポイントの電源を入れ、1分以内に見つけてつながるかを見ます(前は最初の走査より後の走査が始まらず、見つけられませんでした)。
  16. OpenBSDの802.11の層(設計書9.6.9)。`WIFI_NET80211=obsd`で作ったイメージで試します(既定のイメージでは試せません。イメージの作り方は下の「OpenBSDの層のイメージ」)。WPA2-Personal、WPA3-Personal、両方を受け付ける設定(移行モード)のアクセスポイントがあれば、それぞれで試します。
      1. 起動の`KERNEL.TXT`に`iwm0 at pci2 dev 0 function 0`、`obsd: BAR 0x10 at ...`、`iwm0: hw rev 0x230, fw ver 36....`、`wifi: iwm0 ready, address ...`が出るかを見ます。出なければ、その前後の`obsd:`と`iwm0:`の行を持ち帰ります。
      2. 1.〜4.と同じくWPA2で接続し、`wifi: joining "SSID" (...; the layer chooses its access point ...)`、`wifi: authenticating with <BSSID>: PSK, PMF if the access point can: open authentication sent`、`wifi: the 4-way and group key handshakes are done: connected`が出るかを見ます。アクセスポイントがPMFを使える設定なら、`wifi: group key set (BIP, index 4 ...)`の行と、`wifi: link:`の行の`PMF on`が出ます。
      3. 速さ。接続して1分待ち、`wifi: link:`の行の速さを見ます。5GHzの802.11acのアクセスポイントなら`(802.11ac MCS n, 2 streams, 80 MHz ...)`、802.11nなら`(802.11n ...)`と出ます。〈状態〉のタブの速度も写真に撮ります。ブラウザで大きなファイルを落とし、かかった時間を控えます(同じ場所でWindowsのWi-Fiでも同じファイルを落として比べます)。
      4. WPA3。ネットワーク設定で、WPA3-PersonalかWPA2/WPA3を選んで保存し、〈接続〉を押します。`wifi: authenticating with <BSSID>: SAE (H2E)`か`SAE (hunting and pecking)`、`wifi: SAE in: commit ...`、`wifi: SAE in: confirm ...: accepted`、`wifi: SAE done: associating`が出るかを見ます。わざと違うパスワードで試し、`SAE in: confirm ...: given up`の後に「パスワードが違う可能性があります」と出るかも見ます。`wifi: authenticating with`の行から`SAE in: commit`の行までの時間(行の時刻)も控えます(9.6.9の「まだ確かめていないこと」)。
      5. 背景の走査とローミング。同じSSIDのアクセスポイントが2台あるとき、つないだまま、PCを持ってもう1台の近くへ移ります(切れるまで待たずに)。`iwm0: begin background scan`、`iwm0: roaming from ... to ...`、`wifi: roam: <前> -> <今>, <dBm>, <MHz>`の行が出て、通信が続くか(ブラウザのページを開き直せるか)を見ます。1分ごとの`wifi: link:`の行の`background scans N, roams N`が増えるかも見ます。
      6. 切れたとき。アクセスポイントの電源を切り、`wifi: the network was lost ... the layer looks for it again`の行が出て、電源を入れ直すと30秒以内につなぎ直すかを見ます。
      7. 〈走査〉。つないだまま〈走査〉を押し、一覧が新しくなるか(背景の走査)、つながったままかを見ます。
      - 終わったら1分以上待ってから電源を切り、7章の手順でログを持ち帰ります。`KERNEL.TXT`の`wifi:`、`iwm0:`、`obsd:`、`WPA:`で始まる行に各段階が出ます。
  - カードが起動しないとき(`iwm0: could not load firmware chunk`)は、`KERNEL.TXT`の`wifi: irq`の行に、割込みが来たか、カードとMSIのレジスタがどうなっていたか、カードに渡したDMAのメモリの範囲、VT-dの障害記録が出ます(ファームウェアを読んだ3秒後と、起動しなかった直後)。
  - `wifi: DMA REFUSED`の行が出たら、カードに渡しかけたアドレスがカードの届くメモリでなかったことを示します(カードには渡さず、捨て場のページを渡します)。
  - `tsfs: uda1: an error is recorded ...`の行が出たら、システムのボリュームに前の起動の誤りが記録されていて、読取り専用で動いています(設定などは保存されません)。同じ起動の`tsfs: ... ERROR kind`の行が、誤りの見つかった場所です。続けて試すときは、イメージを書き直してください。
  - 起動の早い所(段階「VT-d」)の`vtd:`の行に、ACPIのDMARの表と、VT-dの各単位の状態が出ます。ファームウェアが変換や割込みの再割当てを有効のまま渡していれば、「turned off」の行が出ます。
  - 起動の途中でデスクトップが10秒以上止まると、`!LOCKUP!`の行に、待っているミューテックスの持ち主のタスクが何をしていたか(状態、待っているもの、呼出しの履歴)と、USBの管理の係のロックの持ち主が出ます。止まっても、そのまま1分以上待ってから電源を切ってください。
  - 終わったら1分以上待ってから電源を切り、7章の手順で記録を持ち帰ります。各段階の記録は`KERNEL.TXT`の`wifi:`、`iwm0:`、`WPA:`、`net:`で始まる行にあります(カードの検出、MSI、ファームウェアの読込み、iwmの初期化、走査の結果、認証、関連付け、4ウェイハンドシェイクの各メッセージ、鍵の設定、DHCP)。うまくいかなくても、その行の写真ではなく`KERNEL.TXT`を持ち帰ってください。

### Surface Go 2

- タッチの画面と、Type Coverのキーボードとタッチパッドが動くか。
- USB-Cの口で、USBメモリやアダプタが使えるか。つながらなければ、`cmdline.txt`に`usbrole=host`と書いて起動し直し、もう一度試します。
- 電池、AC、電源ボタン。電池がACPIの標準の形でなければ、`battery0`が出ないことがあります。その場合も記録から調べます。
- USBのLANのアダプタでアドレスが取れるか。

## 7. 記録を持ち帰る

### 止まったとき

画面の写真を撮ります。上端の帯に、そのときの段階の名前が出ています。赤い帯の画面になったときは、例外の種類、レジスタ、直前のコンソールの行が出ているので、画面全体が写るように撮ります。

画面の左下には、ローダの終わりからカーネルの画面の表示が始まるまでの段階ごとに、色の付いた四角(1辺24ドット)が左から順に並びます。どこまで並んだかで、止まった段階が分かります。写真には画面の下端まで写してください。

| 順 | 色 | 段階 |
| --- | --- | --- |
| 1 | 青 | ローダ: 記録を書き終えた |
| 2 | 水色 | ローダ: 記録のファイルを閉じた |
| 3 | 緑 | ローダ: メモリマップを取った |
| 4 | 黄緑 | ローダ: ブートサービスを抜けた(ExitBootServicesが成功) |
| 4 | 黄 | ローダ: ExitBootServicesが断られた(続けてもう一度頼む) |
| 5 | 橙 | ローダ: 2度目のExitBootServicesが成功(4が黄のときだけ) |
| 6 | 赤紫 | ローダ: メモリマップを変換した |
| 7 | 紫 | ローダ: カーネルに飛ぶ直前 |
| 8 | 白 | カーネル: 入口に入った |
| 9 | 灰 | カーネル: 例外の表を作った |
| 10 | 茶 | カーネル: 文字を出す部品の準備ができた |
| 11 | 桃 | カーネル: 画面のコンソールを始めた(この後は帯と文字で出る) |
| 12 | 赤 | 例外(画面のコンソールの前)。続けて白い数字で、例外の番号(2桁)、RIP(16桁)、CR2(16桁)、エラーコード(4桁)を16進で出す |

4の四角は、黄緑か黄のどちらかになります。四角は順に並ぶので、例えば緑(3)まで出て4が無ければ、ExitBootServicesの中で止まっています。

止まったときは、電源ボタンの長押しではなく、可能ならCtrl+Alt+Delなどの温かい再起動をしてください。次の起動でローダが「the last start (n) got to mark 番号」と前回の段階を出し、記録(`LOADER.TXT`)に残します。電源を切るとこの記録は消えます。

### 記録のファイルを取り出す

電源を切ってから、USBの記憶装置をWindowsのPCに挿します。エクスプローラに「TSLOG」という名前のドライブが出るので、その中の`TESSRON`フォルダを丸ごとコピーします。

TSLOGは記録のための区画です。ローダとTessronOSは、ESPの`EFI\TESSRON`と同じ記録を、ここの`TESSRON`にも書きます。取り外しできる装置の2つ目以降の区画にドライブ文字が付くのは、Windows 10 バージョン1703以降です。

挿したときに、Windowsが「ドライブを使うにはフォーマットする必要があります」と聞いてくることがあります。TessronOSのシステムのボリュームは、Windowsが読めない形式だからです。必ず「キャンセル」を押してください。フォーマットすると、TessronOSのシステムのボリュームが消えます。

フォルダには次のファイルがあります。

| ファイル | 中身 |
| --- | --- |
| `LOADER.TXT` | UEFIのローダの記録 |
| `HW.TXT` | CPU、画面のモード、メモリマップ、SMBIOS、ACPIの表の一覧、PCIの全装置、UEFIが見つけたUSBの装置 |
| `ACPI\*.BIN`、`SMBIOS.BIN` | ACPIの表(DSDT、SSDTなど)とSMBIOSを、そのまま保存したもの |
| `KERNEL.TXT` | カーネルのコンソールの記録(起動の20秒後、その後は1分ごとに書く。前に書いてから何も増えていなければ書かない。Wi-Fiの接続の失敗などの出来事の2秒後と、電源を切るときと再起動するときにも書く) |
| `USB.TXT` | カーネルが立ち上げたUSBの装置、ポートごとの状態、速さ、ハブの段数 |
| `ACPI.TXT` | ACPIの名前空間の装置と資源 |
| `DISPLAY.TXT` | Intelの内蔵グラフィックスの表示のレジスタと、解像度を変えたときの手順の記録(最後の節) |

## 8. 起動の設定(cmdline.txt)

起動の設定は、1行のテキストファイル`cmdline.txt`に、空白で区切って書きます。WindowsのPCで、エクスプローラのTSLOGのドライブの直下に`cmdline.txt`をメモ帳で作れば、イメージを作り直さずに試せます。TSLOGに`cmdline.txt`があるときは、ESPの`cmdline.txt`の代わりにそれを使います。

| 設定 | 意味 |
| --- | --- |
| `video=WxH` | 画面のモード(例: `video=2560x1440`)。書かなければThinkPad X1 Yoga 第3世代は1600×1200、ほかは1920×1280以下で最も大きいもの |
| `usbrole=host` | Type-Cの口がホストの役割でないとき、ホストに切り替える |
| `acpi=0` | ACPIの解釈系を起動しない(ACPIの段階で止まるとき) |
| `vtd=keep` | VT-d(IOMMU)をファームウェアが渡したままにする。既定では、ファームウェアが有効のまま渡した変換、割込みの再割当て、保護範囲を、装置を始める前に切ります。記録(`vtd:`の行)はどちらでも出ます。切ったことで起動が止まるようになったときに書きます |
| `hwreport=0` | ローダの報告(`HW.TXT`など)を作らない(報告の途中で止まるとき) |
| `connect=0` | 報告の前に、UEFIの全部のコントローラをつなぎ直さない |
| `keepmode=1` | 画面のモードを変えず、ファームウェアのままにする |
| `memtype=custom` | カーネルの領域を、以前のローダと同じOS用の独自のメモリの種類(0x80000001)で確保する(比べるため) |
| `lastlog=0` | ブートサービスを抜ける直前に、記録(`LOADER.TXT`)をもう一度書かない |
| `tslog=0` | ローダはTSLOGに記録を書かない(TSLOGの`cmdline.txt`は読む。カーネルは書く) |
| `stopat=名前` | 名前で始まる段階で止まり、画面を残す(例: `stopat=USB`) |
| `faultat=名前` | その段階でわざと例外を起こし、止まったときの画面を確かめる |

止まった場所によって、どの設定を書けばよいかを伝えます。

## 9. 終わったら

Windowsに戻すときは、BIOSの設定(X1 YogaはF1、Surfaceは音量の上げるボタンと電源ボタン)でSecure Bootを有効に戻します。BitLockerを一時停止していたときは、再開します。回復キーを求められたら、2章で控えたキーを入れます。

## 10. ThinkPad X1 Carbon(型番21CB)で起動する

設計書3.10.12の機種です。機種の構成はまだ確かめていません。この手順の目的は、まず記録を持ち帰ることです。

1. Windowsで、BitLockerの回復キーを控えます(2章)。Secure Bootを切ると、次のWindowsの起動で回復キーを聞かれることがあります。
2. 電源を入れてF1を押し、ファームウェアの設定を開きます。Security、Secure BootでSecure Bootを無効にします。ほかの設定は変えません。設定の変更前の値を写真に撮っておきます。
3. 同じ設定の画面で、Config、Storageの項目と、Thunderboltの起動前の支援の項目の値を写真に撮ります。変えなくて構いません。
4. 3章のとおりに書いたUSBの記憶装置を挿します。この機種に普通のUSB-Aの口があればそちらに挿します。
5. 電源を入れてF12を押し、起動のメニューからUSBの記憶装置を選びます。
6. 上の帯の文字と、止まったら画面全体を写真に撮ります。動いているように見えても、2分は電源を切りません(記録は20秒後と、その後は1分ごとに書きます)。
7. 止まったままのときは電源ボタンの長押しで切ります。電源を切る前に、最下行の赤い見張りの行を撮ります。
8. 7章のとおりに、USBの記憶装置のTSLOGの`TESSRON`を丸ごと持ち帰ります。

機械が勝手に再起動をくり返すときは、そのまま次の起動まで進めてから電源を切り、`LOADER.TXT`を持ち帰ります。`the last start ... while starting the processor of APIC 番号`の行が、どのプロセッサでリセットしたかを示します。

持ち帰るもの: `HW.TXT`、`LOADER.TXT`、`KERNEL.TXT`(あれば`KERNEL1.TXT`も)、`USB.TXT`、`ACPI.TXT`、`ACPI`のフォルダ、`SMBIOS.BIN`、画面の写真。
