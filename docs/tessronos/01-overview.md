# 第1章　概要

## 1.1 TessronOSとは

TessronOSは、μT-Kernel 3.0を出発点に、64bit化、マルチプロセッサ対応、プロセスとメモリ保護、実身/仮身のファイルシステム、ウインドウシステムとデスクトップを積み上げたOSである。対象はRaspberry Pi 5(Broadcom BCM2712、Cortex-A76 ×4)で、開発と試験の大半はQEMUの`virt`マシンで行う。

μT-Kernel 3.0は32bitマイコン向けの小さなリアルタイムカーネルで、MMUもマルチプロセッサもプロセスも持たない。一方、TRONプロジェクトにはそれらを扱う仕様が既にある。SMP T-Kernel仕様はマルチプロセッサを、T-Kernel 2.0 Extension(T2EX)はメモリ保護とファイル管理とプログラムのロードを、BTRONは実身/仮身とレイヤ構成を定めている。TessronOSは、これらの仕様を、読みやすいμT-Kernel 3.0のソースコードを土台に、64bit CPUに合わせて再構成したものである。

## 1.2 主な特徴

| 特徴 | 内容 |
| --- | --- |
| 64bit | AArch64で動く。仮想アドレスは48bit、カーネルは上位半分の空間に置き、プロセスは下位半分に固有の空間を持つ。`INT`・`UINT`は32bitのまま残し、サイズとアドレスは64bitの型で扱う(4.1) |
| SMP | 4つのCPUで動く。レディキューは全体で1本で、優先度の高いタスクから順に空いているCPUへ割り当てる。タスクは実行プロセッサを指定できる。カーネル内の排他制御はスピンロックで行う(第4章) |
| プロセス | EL0で動く保護レベル3のプロセスが固有のアドレス空間を持ち、ELF形式のプログラムをロードして実行する。システムコールはSVC命令の機能コードで呼ぶ(第5章) |
| 実身 | ファイル、メモリ、デバイス、プロセス、通信路、ウインドウ、部品を、128bitのUUIDで識別する「実身」として同じ操作で扱う(第8章) |
| TSFS | 実身をそのまま格納するファイルシステム。xmlTADの実身をUUIDで管理し、TADjs Desktop形式のファイル群と相互に変換できる(第7章) |
| 画面 | 描画、フォント、ウインドウ、部品、パネル、メニューを備えたウインドウシステムと、BTRONの操作環境を再現するデスクトップ(第10章、第11章) |

## 1.3 できること

2026年9月末の時点で、次のことができる。

- QEMUとRaspberry Pi 5で起動し、4つのCPUでタスクとプロセスを実行する。
- SDカード、USBメモリ、virtioのディスクを読み書きする。FAT12/16/32とTSFSを扱う。
- TCP/IPで通信する。DHCPでIPアドレスを取得し、DNSで名前解決し、SNTPで時刻を合わせる。
- デスクトップを起動し、仮身一覧、基本文章編集、基本図形編集で実身を作り、編集し、保存する。かな漢字変換で日本語を入力する。
- 時計、コンソール、シリアル通信、書庫解凍、バックアップ、ファイル変換、ネットワーク設定、システム環境設定、ユーザ環境設定を、プロセスとして実行する。
- Chromium 153のBlinkとV8を移植したブラウザで、HTTPSのWebサイトを表示する(第14章。別のリポジトリ`tessron-chromium`から取り込む)。

## 1.4 やらないこと

TessronOSは汎用のPOSIX OSを目指さない。POSIXの関数はプログラムの移植に必要な範囲でライブラリとして用意するが、BTRONの実身モデルとT-KernelのAPIを優先する。対象ハードウェアはRaspberry Pi 5とQEMUの`virt`に限り、他のボードへの移植は予定していない。

## 1.5 ライセンス

μT-Kernel 3.0に由来する部分はT-License 2.2に従う。新しく書いた部分もT-License 2.2とする。T2EXとはシステムコールの名称と引数を合わせているが、T2EXのソースコードは含まない。外部から取り込んだソフトウェア(FreeType、NetBSDのネットワークスタック、lwIP、Mbed TLS、newlibなど)は、それぞれのライセンスに従う。取り込んだソフトウェアの入手元とバージョンは`UPSTREAM.md`と`THIRD_PARTY_NOTICES.md`にまとめてある。
