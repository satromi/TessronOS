# 第11章　デスクトップとアプリケーション

## 11.1 デスクトップ

起動すると、デスクトップが背景(壁紙)を表示し、最初のキャビネットをウインドウで開いて、ユーザの操作を待つ。起動時、実身のボリュームがまだ接続されていないときだけ、`/boot`(FAT)にある実身の写しを実身の置き場として接続する。システムボリュームがあるマシンで`/boot`も接続すると、同じ実身が2つのボリュームに見えるためである。書体箱のフォントは、同じファミリーのフォントがすでに開いていればそれを使い、二重には開かない。デスクトップはカーネルのタスクとして動き、キャビネット、基本文章編集、基本図形編集もその中にある。描画は第10章の描画管理とウインドウマネージャが行い、デスクトップは何をいつ表示するかを決めるだけである。画面の大きさは画面の実身から読み、機器の設定の解像度にするときもその実身に書く(8.4)。試験などでデスクトップを終了させると、ウインドウを閉じ、壁紙とメッセージ行を取り下げ、システムの実身の電源のレコードとの結び付きを外して、ウインドウシステムを起動前の状態に戻す。

操作は超漢字Vに合わせてある。

| 操作 | 機能 |
| --- | --- |
| 右ボタン | ポインタの下にあるウインドウのメニューを開く |
| タイトルバーをドラッグ、右下の角をドラッグ | ウインドウを移動する、サイズを変える |
| 仮身をダブルクリック | その実身を、`applist`で既定の起動に指定されたプログラムで開く |
| 仮身をウインドウへドラッグ&ドロップ | そのウインドウに仮身を置く |
| Ctrl+S、Ctrl+E | 最前面のウインドウを保存する、保存して閉じる |
| Ctrl+A、C、X、V、Z | すべて選択、コピー、切り取り、貼り付け、トレーから移動 |
| Ctrl+L、F、R、D | 全画面表示、最前面へ、最背面へ、整列 |
| Delete | 選択したものを削除する |
| Shift+Pause | 最前面のウインドウを作ったプロセスを強制終了する。カーネルのウインドウ(デスクトップ、キャビネット、編集)とシステムに必要なプロセスは終了させない(5.5.1) |

どのウインドウのメニューにも、先頭に「閉じる」、末尾に「仮身操作」「実身操作」「屑実身操作」「ウインドウ」「小物」「実行」が出る。これらはシステムのメニュー定義にあり、各プログラムのメニュー定義が取り込む(10.8)。「ウインドウ」は開いているウインドウを前面にあるものから順に一覧表示し、選択したウインドウを最前面に出して入力フォーカスを移す。プロセスとして動くアプリケーションのメニューにも「ウインドウ」があり、一覧の作成と選択したウインドウの切替えはシステムが行う。「取消」で直前の変更を元に戻せる。

### プログラムの異常終了

プロセスが例外で終了すると、デスクトップは「プログラムの異常終了」というウインドウを画面の中央に表示する(5.5.2)。表示する内容は次のとおりである。

| 項目 | 内容 |
| --- | --- |
| プログラム | プログラムの実身名(実身から起動していなければファイル名)とプロセスID |
| 例外 | 例外の種類。`ESR`の例外クラスと要因から、データアボート(マップされていないアドレスへの書込み、アクセスを許されていないアドレスからの読出しなど)、命令アボート、未定義命令、アライメント例外、不正な実行状態、浮動小数点例外などの日本語にする |
| アドレス(FAR) | アクセスしようとしたアドレス |
| PC(ELR)、LR | 例外を起こした命令のアドレスと、その時点のx30 |
| 終了コード | `TS_ABORT_FAULT`(-256)か`TS_ABORT_ILL`(-257) |
| 詳細 | 例外を起こしたタスクのID、`ESR`と例外クラス |

システムコールに不正なアドレスを渡して終了したときは、その旨を見出しに示し、PCとLRはカーネル内の値として表示する。ウインドウは最前面に出すが、入力フォーカスは移さない。ほかのウインドウに入力している文字がダイアログに入らないようにするためである。「了解」を押すか、ピクトグラムをダブルクリックすると閉じる。入力フォーカスがあるときは、EnterかEscapeでも閉じる。

このウインドウは1つだけ開く。表示している間に次の例外が起きると、内容を最新の例外に置き換え、「このほかにN件、例外で終了したプログラムがあります」と表示する。件数には、カーネルのキューからあふれて捨てた記録も含む。ダイアログはカーネルの記録を読んで`dt_pn_*`でパネルを組み立て、ウインドウのパネルとして開く(`application/desktop/dtfault.c`)。管理情報と同じく、デスクトップの主ループがこのウインドウの事象を先に渡す通常のウインドウで、デスクトップの操作を止めない。

## 11.2 プログラムの実身

プログラムも実身である。プログラムの実身のメタデータ`tessronos.program`が、そのプログラムの種類と属性を示す。

```json
"tessronos": { "program": { "id": "basic-text-editor", "kind": "app",
  "name": "基本文章編集", "version": "R1.000", "base": [ "UUID" ], "builtin": true } }
```

`id`は実身の`applist`で参照される識別子で、TADjs Desktopが作成した実身は、そこに記載されたプログラムでそのまま開ける。`kind`は次の3種類である。

| kind | 内容 | 登録先 |
| --- | --- | --- |
| `app` | 原紙を持ち、実身を開いて編集するアプリケーション | プログラム箱、原紙箱 |
| `accessory` | 独自のデータを持たない小物 | 小物箱 |
| `utility` | システムのツール | プログラム箱 |

デスクトップに組み込まれたプログラムは`builtin`で、実行ファイルを持たない。プロセスとして動くプログラムは、実行ファイルを型9のレコードに持ち、実身を開くときや小物箱から起動するときにプロセスとして起動される(第5章)。

プロセスの起動は、デスクトップのタスクではなく、起動専用のタスクが行う(`application/desktop/dtprog.c`)。ポインタを動かし、ウインドウの移動を処理するのはデスクトップの主ループなので、デスクトップのタスクがプログラムを読み込むと、その間は画面全体が止まる。デスクトップはプログラムの実身と開く実身を起動のタスクに渡し、すぐに主ループへ戻る。起動のタスクは最初の起動のときに作られ、優先度はデスクトップ(20)のすぐ下の21である。依頼は8件まで待たせ、受けた順に処理する。プロセスがデスクトップに実身を開くことや小物の起動を依頼したとき(マイクロスクリプトの`VOPEN`など)は、起動のタスクがプロセスを生成してから、そのプロセスを入れて依頼元に応答する。起動できなかったときは、メッセージ行に「<プログラム名>を起動できませんでした」と表示する。小物を名前で起動する依頼では、表示せずに応答のエラーで知らせる。

TADjs Desktopのプラグインの登録情報(`plugin.json`と原紙の組)は、`/boot/PLUGINS`の下に置いておくと、デスクトップが起動時にプログラムの実身と原紙の実身として取り込む。プラグインのコード(HTML)は動作しないので、取り込むのは名前、`applist`の`id`、原紙である。

## 11.3 デスクトップ内のアプリケーション

| アプリケーション | 内容 |
| --- | --- |
| キャビネット | 仮身を並べる。仮身の選択、移動、サイズ変更、削除、コピーができる。表示形式(アイコン、名前、実身の内容)を仮身ごとに持つ |
| 基本文章編集 | xmlTADの文章を編集する。段落と文字の書式、仮身と画像の貼り付け、正規表現による検索と置換、用紙設定 |
| 基本図形編集 | xmlTADの図形を編集する。直線、折れ線、曲線、矩形、角丸矩形、楕円、扇形、弓形、多角形、文字枠、仮身、画像。回転、反転、グループ化、前後関係、整列、パターン |
| 屑実身操作 | どこからも参照されなくなった実身の一覧。取り出すか、完全に削除する |
| 実身/仮身検索 | 名前、続柄、内容の文字列、日付で実身を検索する |
| 仮身ネットワーク | 実身が参照する実身を階層ごとに並べ、矢印で結ぶ |

図形の計算には浮動小数点を使わない。角度は1周を4096等分した値、正弦は16384倍した整数で扱う。

### 管理情報

「実身操作」の「管理情報」は、仮身が指す実身の管理情報を1つのウインドウで開く。ダイアログではなく通常のウインドウなので、ほかのウインドウと並べて開いておける。同じ実身の管理情報がすでに開いていれば、そのウインドウを最前面に出す。ウインドウは「実身情報」「使用者管理」「付箋指定」の3つのタブを持ち、変更した内容は「適用」で書き込まれ、「取消」では何も書き込まずに閉じる。

| タブ | 内容 |
| --- | --- |
| 実身情報 | 実身名、UUID、続柄、作成者、作成日時、更新日時、参照日時、サイズ、レコード数、参照仮身数、含む仮身数 |
| 使用者管理 | 所有者とグループ、所有者・グループ・一般それぞれの読出し・書込み・実行の権限、編集不可と削除不可、個別の利用権 |
| 付箋指定 | 機能付箋(その実身を開けるプログラム)の一覧と、既定の起動、起動固定 |

使用者管理は、BTRONの所有者・グループ・一般の利用権を基に、削除不可の属性と、ユーザやグループごとの個別の利用権を加えたものである。内容は実身の保護情報(8.6)で、所有者か管理者だけが変更できる。書き込むとメタデータの`editable`と`deletable`も合わせて更新されるので、TADjs Desktopから見ても同じ意味になる。

付箋指定の一覧で選択した機能付箋(緑の横棒が付く)が、ダブルクリックで開くときの既定の起動である。機能付箋は、システムに登録されたプログラムから「追加」で選ぶので、指定されるのは必ず起動できるプログラムになる。ウインドウのメニューの「編集」にある「コピー」は、選択した機能付箋をプログラムの実身への仮身としてトレーに入れ、「貼り付け」はトレーの仮身が指すプログラムを一覧に加える。これにより、ある実身の機能付箋を別の実身に貼り付けられる。プログラム箱や原紙箱から取った仮身も貼り付けられる。

起動固定は仮身ごとの設定である。起動固定していない仮身から「実行」で別のプログラムを選んで開くと、そのプログラムが以後の既定の起動になる。起動固定した仮身では既定の起動は変わらない。

## 11.5 マイクロスクリプトの通信機能

マイクロスクリプトは、TADjs Desktopで追加された通信用の命令を同じ仕様で持つ。仮身サンプルの通信用スクリプトはそのまま動く。

| 命令 | 機能 |
| --- | --- |
| `HTTPREQ メソッド, URL[, ヘッダ][, 本文]` | HTTPかHTTPSでリクエストを1回送り、レスポンスを待つ。ヘッダは「名前:値」の行 |
| `HTTPHDR 変数, 名前` | 直前のレスポンスのヘッダの値。名前の大文字と小文字は区別しない |
| `JSONGET 変数, パス`、`JSONLEN 変数, パス` | 直前のレスポンスのJSONの値と要素数。パスは`result.tools.0.name`の形式で、ドットを含む名前は後続の部分と連結して検索する |
| `SPRINTF 変数, 書式[, 引数…]` | 書式どおりの文字列を変数に格納する |
| `TCPOPEN`、`TCPSEND`、`TCPWAIT`、`TCPRECV`、`TCPCLOSE` | TCP接続。RS系の命令がシリアル回線を扱うのと同じ形式 |
| `CONSOLE 1` | ウインドウ全体をメッセージの表示に使う。`CONSOLE 0`で元に戻る |

システム変数は`$HTTPST`(ステータスコード)、`$HTTPLEN`と`$HTTPBODY[i]`(本文)、`$TCP[i]`、`$TCPCNT`、`$TCPST[n]`である。レスポンスが`text/event-stream`のときは、その中のJSONメッセージのうちリクエストへの応答(`result`か`error`を持つもの)をJSONとして扱う。書式の`%s`や通信用の命令に配列名だけを渡すと、要素0ではなく配列全体を文字列として扱う。

HTTPSはMbed TLSによるTLS 1.2と1.3で、接続先のサーバ証明書を、実身「ルート証明書」(システム箱)にある認証局の証明書とホスト名で検証する。

初めて接続するホストには、ウインドウに接続の許可を確認するパネルが表示される(許可はYかEnter、拒否はNかEsc)。許可したホストは図形の実身のメタデータ`networkGrants`に記録され、次回からは確認しない。

`localhost`はTessronOS自身を指す。仮身サンプルのMCP用スクリプトはlocalhostの3333番と3334番のサーバに接続するので、PCで動くサーバを使うときはスクリプトのURLをそのPCのアドレスに書き換える。

## 11.6 設定の小物

ネットワーク設定、システム環境設定、ユーザ環境設定の3つは、ウインドウの内容をすべてカーネルの部品で構成する。パネルの定義は小物ごとのデータボックス実身(`SYSDEF_BOX_NETENV`、`SYSDEF_BOX_SYSENV`、`SYSDEF_BOX_USERENV`)にあり、プログラムはパネルを配置して部品を番号で読み書きするだけで、描画はしない(10.7)。ウインドウの上端にはタブパネルがあり、タブを押すとそのページの部品に切り替わる。

| 小物 | 設定の書込み先 |
| --- | --- |
| ネットワーク設定 | ネットワーク設定の実身のレコード1(9.3)。「設定を更新」を押したとき、または保存して閉じたときに書き込み、監視タスクがそれを反映する |
| システム環境設定 | システムの実身のレコード(8.4)、画面の実身とデバイス設定の実身。壁紙と配色はすぐに切り替わり、再起動と電源断もここから要求する |
| ユーザ環境設定 | 外観設定テーブルの設定項目(10.5)。変更した値はすぐに反映され、閉じるときに保存するかどうかを確認する。保存する値はユーザ情報の実身に、タイムゾーンは暦の実身に、NTPサーバはネットワーク設定に書き込む |

## 11.7 かな漢字変換

文章のウインドウと部品のテキストボックスは、テキスト入力ポートを通してかな漢字変換を使う(10.10)。入力モードは日本語と英字の2つで、メッセージ行に「Rあ」「Ra」のように表示する。変換エンジンの学習データは学習箱の実身に格納する。

## 11.8 バージョンとアプリケーションのパッケージ

バージョンは`R1.000`の形式で書く。`R`、桁数が可変の整数、ピリオド、3桁の数字からなり、比較するときは整数部を1000倍して3桁の数を足した値として比較する。アプリケーションのバージョンはプログラム実身のメタデータ`tessronos.program.version`に書き、システムのバージョンはビルド時の`TS_VERSION`で決まる。現在はシステムもすべてのアプリケーションも`R1.000`である。

システム環境設定の〈バージョン〉は、最上部にシステムのバージョンを表示し、その下の一覧にプログラム箱のアプリケーションの名前を並べ、名前の右端にバージョンを表示する。一覧で選択して〈詳細情報〉を押すと、名前、バージョン、識別子、種類、実身のUUID、組み込みかどうかを表示する。

アプリケーションはパッケージ(.tpk)で配布する。パッケージは、プログラム実身と原紙の実身を、システムの実身と同じファイル形式(`{uuid}.json`、`{uuid}_N.xtad`、`{uuid}_N.bin`、`{uuid}.ico`)のまま1つにまとめ、`package.json`にプログラムの実身、識別子、バージョンを記載したものである。`tools/mktpk.py`か`make pkg PKG=<id>`で作成する。

| 操作 | 機能 |
| --- | --- |
| パッケージの仮身を〈バージョン〉の一覧にドロップする | インストールする。同じ識別子のアプリケーションがあれば、パッケージのほうが新しいときだけ更新し、同じか古いときは置き換えるかを確認する |
| 一覧で選択し、メニューの〈操作〉から〈削除〉 | 確認してから、そのアプリケーションをプログラム箱から外し、プログラムの実身と原紙の実身を削除する。システムに組み込みのアプリケーションは削除できない |

外部から持ってきたパッケージは、ファイル変換で取り込むと、ファイルの内容をレコード1に持つ実身になる。その仮身を一覧にドロップすればよい。インストールと削除はデスクトップが行い(`DT_RQ_INSTALL`、`DT_RQ_REMOVE`)、管理者のプロセスからの要求だけを受け付ける。プログラム箱を読み直すので、小物メニューや原紙箱にもすぐに反映される。

## 11.9 ファイル変換

ファイル変換は、FATのメディアやFTPサーバにあるファイルと、TessronOSの実身とを相互に変換する小物で、プロセスとして動く(`application/xfconv/`)。変換処理は`lib/libxfu`にあり、カーネルの`xf_`と同じ規則でファイルを実身に、実身をファイルに変換する。確認用のパネルはデータボックス実身`SYSDEF_BOX_XFCONV`で定義し、ウインドウの部品として表示する。

### メディアの一覧

起動すると「ファイル変換」のウインドウに、デバイス管理が認識しているディスク(パーティションを含む)を青い仮身で並べ、続けて「ネットワーク(FTP)」と、保存したFTPの接続を並べる。ディスクの仮身には容量と、マウント済みならマウント先を付けて表示する。メディアが入っていないディスクは薄く表示する。

ディスクの仮身をダブルクリックするか、選択してEnterを押すと、マウントしていなければ自動でマウントし、新しいウインドウにそのボリュームのルートにあるファイルとディレクトリを仮身で表示する。ウインドウのタイトルはディスク名である。複数のウインドウを同時に開ける。読取り専用でマウントするかどうかはメニューで選び、Ctrl+Mで選択したディスクのマウントとアンマウントを切り替える。

### ファイルの一覧

ファイル一覧のウインドウでは、仮身の色で種類を示し、ファイルの仮身の後ろにサイズを表示する。

| 色 | 種類 |
| --- | --- |
| 青 | ボリューム(先頭。開くとルートへ戻る) |
| 水色 | 親ディレクトリ |
| 緑 | ディレクトリ |
| クリーム | 隠しディレクトリ(名前がピリオドで始まる) |
| 灰 | ファイル |
| 白 | 隠しファイル |

ディレクトリの仮身をダブルクリックすると、そのディレクトリへ移動する。メニューの〈ディレクトリ〉には、親ディレクトリ、ルート、これまでに開いたディレクトリの履歴が並ぶ。仮身はクリックで選択し、Shiftを押しながらクリックで追加選択し、何もない場所からドラッグして矩形で囲むとまとめて選択できる。キー操作では、矢印キーで移動し、Shift+矢印キーで範囲を選択し、Spaceで1つずつ選択する。一覧がウインドウに収まらないときは、スクロールバー、ホイール、PageUp、PageDownでスクロールする。

ウインドウを閉じると、そのウインドウでマウントしたボリュームをアンマウントする。取り外せるメディアなら、取り出してよいことをメッセージ行に表示する。FTPのウインドウを閉じると接続を切断する。

### ファイルから実身へ

選択した仮身をファイル一覧のウインドウからドラッグすると、デスクトップがその外形をポインタに合わせて動かす(`DT_RQ_CARRY`)。図形、仮身一覧、文章のウインドウの上でドロップすると、変換方法を選ぶパネルが表示される。

| 変換方法 | 機能 |
| --- | --- |
| 自動 | ファイルの先頭部分と拡張子で種類を判定する(文章、画像、xmlTAD、書庫、その他) |
| 文章(全角/半角混在) | 文章として変換する。文字コードは自動判定(Shift_JIS、EUC-JP、ISO-2022-JP、UTF-8)か、パネルで選んだもの |
| 文章(全角のみ) | 英数字と記号を全角に、空白を全角空白に、半角カナを全角カナ(濁点と半濁点は結合)に変換する |
| 画像 | BMP、JPEG、PNG、GIFを図形内の画像として変換する。1/2、1/4、1/8に縮小できる |
| 無変換(基本) | バイト列をそのままレコード1に格納し、レコード0にはファイル名だけを書く |
| 書庫(BPK) | BTRONの書庫として扱い、開くと書庫解凍が起動する |

〈実行〉を押すと、ドロップ先のウインドウの実身と同じボリュームに実身を作成し、それぞれへの仮身を、ドロップした位置に一覧での並び順のまま配置する(`DT_RQ_PLACE_MORE`と`DT_RQ_PLACE`)。デスクトップの背景やファイル一覧のウインドウの上でドロップしたときは何もしない。どの変換方法でも、ファイルのバイト列はレコード1にそのまま残るので、書き出すと元のファイルに戻る。ディレクトリは中のファイルを自動判定で変換し、仮身を並べた図形にする。TADjs形式のファイル群は、それを含むディレクトリを変換すると実身に戻る。

キー操作では、選択したものをCtrl+Iで変換する。このときは同じパネルを表示した後、ファイル変換の箱に「取込 名前」という新しい箱(仮身一覧)を作って仮身を入れ、デスクトップにその箱を開かせる。

### 実身からファイルへ

デスクトップの仮身をファイル一覧のウインドウにドロップすると、出力のパネルが表示される。1つだけのときは出力ファイル名を変更でき、空欄にすると実身の名前から付ける。

| 変換方法 | 機能 |
| --- | --- |
| 自動 | 取り込んで変更していない実身は元のファイルに、文章はテキストファイルに、仮身を並べた図形はディレクトリに変換する |
| 文章(Shift_JIS)、文章(UTF-8) | 文章をその文字コードのテキストファイルにする |
| xmlTAD(無変換) | 実身のレコード0をそのまま`.xtad`ファイルにする |
| TADjs形式 | 実身と、その実身が仮身で参照する実身を、TADjs形式のファイル群(`{uuid}.json`、`{uuid}_N.xtad`など)にする |

〈図形の配置も書き出す〉を選ぶと、ディレクトリに変換した図形のxmlTADもディレクトリ内に残す。出力先はウインドウが表示しているディレクトリで、ディレクトリの仮身の上にドロップすればその中に出力する。書き出したファイルは一覧に選択された状態で表示される。キー操作では、Ctrl+Oで、起動時に指定された実身(または最後に取り込んだ実身)を同じパネルを通して書き出す。

### FTP

「ネットワーク(FTP)」を開くと、接続のパネルが表示される。接続先(ホスト)、ポート(21、SSHのときは22)、SSHを使う、ユーザ名、パスワード、パスワードを保存する、パッシブモード、アクティブモードのポート、ファイル名の文字コード(UTF-8、Shift_JIS、EUC-JP)、接続名を入力して〈接続〉を押すと、ディスクと同じようにファイル一覧のウインドウが開く。接続できなかったときは、理由をパネルの下部に表示し、パネルはそのまま残る。

接続設定はプログラム実身のメタデータ`tessronos.xfconv`に保存し、メディアの一覧に接続名(なければ`ftp://ユーザ@ホスト`)で表示する。パスワードは、保存を選んだときだけ平文で保存される。SSH(SFTP)はまだ実装していないので、SSHを選んで〈接続〉を押すと、使えないことをパネルに表示して接続しない。

### コンソールへの出力

ファイル変換は、処理の内容をコンソールに`xfconv: `で始まる行で出力する。試験はこの出力を読む。

| 行 | 意味 |
| --- | --- |
| `media 名前 容量 マウント先` | メディアの一覧の1行 |
| `mounted パス`、`unmounted 名前` | マウントとアンマウント |
| `window 名前` | ファイル一覧のウインドウを開いた |
| `dir パス N entries`、`- 名前 サイズ` | 一覧を読み込んだ |
| `selected N: 名前, …` | 選択中のもの |
| `carried N into UUID` | ドラッグ先のウインドウの実身 |
| `asked how to import N: 名前`、`asked how to export N: 名前` | パネルを表示した |
| `imported M of N objects K box UUID first UUID` | 新しい箱へ変換した |
| `imported M of N objects K into UUID first UUID`、`placed N links` | ドロップ先へ変換し、仮身を配置した |
| `exported 名前 files N objects N skipped N` | 書き出した |
| `connected ホスト 文字コード 方式`、`disconnected URL`、`ssh not supported` | FTPの接続 |

`tests/ktest/ktest_xfc.c`はキーとポインタのイベントでウインドウを操作し、`tests/ktest/ktest_drop.c`はデスクトップを動かして、仮身をドロップしての書き出しと、ファイルを図形へドラッグしての変換を確認する。画面は`tools/tests/ui_xfconv.steps`を`tools/ui_run.py`で実行して確認する(12.4)。
