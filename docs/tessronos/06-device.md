# 第6章　デバイス

## 6.1 デバイス管理

デバイスは、μT-Kernel 3.0のデバイス管理機能で扱う。ドライバは`tk_def_dev`でデバイスを名前で登録し、利用側は`tk_opn_dev`で開いて`tk_rea_dev`、`tk_wri_dev`で読み書きする。パーティションを持つディスクは、パーティションをサブユニットとして見せる(`sda`がデバイス全体、`sda0`が第1パーティション)。

登録するデバイスは次のとおりである。

| 名前 | 種類 | ハードウェア |
| --- | --- | --- |
| `sda` | ディスク | SDカード(SDHCI) |
| `vblka`、`vblkb` … | ディスク | virtio-blk(QEMU) |
| `uda`、`udb` … | ディスク | USBマスストレージ。接続した順に名前が付く |
| `neta` | ネットワーク | Ethernetかvirtio-net。1回の読み書きが1フレーム |
| `snda` | サウンド | USBオーディオ、RP1のI2S |

次のものはデバイス管理には登録しない。このうち実身があるものは、デバイスマネージャが実身として見せ、プログラムは実身を通して使う(8.4)。

| もの | 扱い | 実身 |
| --- | --- | --- |
| コンソールのUART | カーネル内の関数(`tm_`) | なし(起動の最初から使う) |
| RTC | カーネル内の関数。時刻は時計の実身で見せる | 時計 |
| 乱数 | 実身。カーネル内の利用者は`ts_get_random` | 乱数(`OB_S_CHAR`) |
| 画面 | 実身。描画の層は`ts_disp_`を直接使う | 画面(`OB_S_DISPLAY`) |
| USBのキーボードとマウス | 実身。ウインドウマネージャは`ts_hid_read`で受け取る | インタフェースごとのキーボード、ポインタと、入力(`OB_S_INPUT`) |
| GPIOのバンク(Raspberry Pi 5) | 実身。ドライバがピンを機能に割り当てる処理は`gpio_`、`rp1_gpio_`を直接使う | バンクごと(`OB_S_GPIO`) |
| USBデバイス(ハブを含む) | 実身 | デバイスごと(`OB_S_USB`) |

デバイスは実身としても扱える。デバイスの実身に対するレコードの読み書きが、そのままデバイスの読み書きになる(第8章)。デバイスのUUIDは最初に検出したときに生成してデバイス箱に記録するので、次回の起動でも同じ実身として見つかる。USBメモリのように抜き差しのあるデバイスの接続・切断、メディアの挿入・取出しは、そのデバイスの実身とデバイス一覧の実身へのイベントとして通知される。ディスクのボリュームは、デバイスの実身を通して`fs_attach_dev`で要求すると`/media`の下にデバイス名でマウントされ、デバイスが切断されるとアンマウントされる。

## 6.2 ドライバ

| ハードウェア | ファイル | マシン | 状態 |
| --- | --- | --- | --- |
| PL011 UART | `device/ser/ser.c` | 両方 | 起動時のコンソール。送信はポーリング、受信は割込み(割込みが来なかったバイトも読出し時にFIFOから取り出す) |
| RP1 UART | `device/ser/uart_rp1.c` | Pi 5 | 40ピンヘッダのUART |
| SDHCI | `device/sd/sdhci.c` | 両方 | SDカードの読み書き |
| virtio-blk | `device/vblk/vblk.c` | QEMU | 試験用のディスク |
| virtio-net | `device/vnet/vnet.c` | QEMU | ネットワーク |
| RP1 Ethernet | `device/net/eth_rp1.c` | Pi 5 | Cadence GEM、Gigabit |
| GPIO | `device/gpio/gpio_bcm2712.c`、`gpio_rp1.c` | Pi 5 | 基板上のLEDと40ピンヘッダ。バンクごとの実身(`peripheral_kernel/obj/obgpio.c`) |
| 画面 | `device/disp/` | 両方 | Pi 5はファームウェアが用意するフレームバッファ、QEMUは`bochs-display` |
| USB | `device/usb/` | 両方 | xHCI、ハブ、HID、マスストレージ、オーディオ |
| サウンド | `device/snd/` | 両方 | サウンドデバイスとRP1のI2S |
| GPU | `device/gpu/` | 両方(V3DはPi 5) | 共通層とV3Dのアドレス空間は両方で試験済み。V3Dのドライバは識別、MMUの設定、キャッシュのジョブまで実機で確認(第13章) |

PCIeのコンフィギュレーション空間はECAMで読み、列挙時にBARを割り当てる。Raspberry Pi 5では、RP1が接続されたPCIeのルートコンプレックスをカーネルが自前で初期化し、RP1のアドレスウインドウを通してUSB、Ethernet、GPIO、UARTにアクセスする。PCIeデバイスのMSIはエッジトリガで受け付ける。

## 6.3 USB

USBスタックは、xHCIホストコントローラの上に、ハブ、HID、マスストレージ、オーディオのクラスドライバを載せたものである。Low、Full、High、Superのすべての速度と、コントロール、バルク、インタラプト、アイソクロナスの各転送を扱う。デバイスの抜き差しは、専用の管理タスクがハブの状態変化を受けて処理する。管理タスクは、デバイスが来たり去ったりすると、ロックを放した後でUSBデバイスとキーボード、ポインタの実身を一覧に合わせる(`knl_obusb_changed`)。

| クラス | 機能 |
| --- | --- |
| HID | キーボードとマウス。レポートディスクリプタを解析し、相対座標と絶対座標のどちらも扱う |
| マスストレージ | Bulk-Only TransportとSCSI。パーティションテーブルを読み、パーティションをサブユニットにする |
| オーディオ | UAC 1.0。アイソクロナス転送で再生と録音をする |
| ハブ | USB 2.0とSuperSpeed |

## 6.4 キーボードとポインタ

キーボードとマウスの入力は、USBのHIDから入力キューに入り、ウインドウマネージャが読み出す。同じイベントの写しを、インタフェースごとの実身と入力の実身がレコード1で見せる。写しを読んでもキューからは取り出さない。試験などが与える入力は、入力の実身のレコード1に書き込み、キューに入る(8.4)。ユーザ環境設定で変更できる入力の属性、たとえばキー入力の受付時間、キーリピート、ポインタの速度と加速度、主ボタンの左右の入れ替え、中ボタンのダブルクリック割当て、一時シフトは、このレイヤで適用する。ホイールは縦と横の回転量として通知される。

HIDのインタフェースは次のように準備する。ブートサブクラスのキーボードは、SET_PROTOCOLでブートプロトコルに切り替え、SET_IDLE(0)を送り、SET_REPORTでLEDをすべて消す。LEDが一度設定されるまでレポートを送らないキーボードがあるためである。8バイトのブート形式のレポートを読み、キーの配列にErrorRollOverなどの誤り(値1から3)があるときは、キーの状態を前のレポートのままとし、修飾キーだけを更新する。同時押しが多すぎたときに、押されているキーを離して押し直したことにしないためである。

ポインタは、レポートディスクリプタ(4096バイトまで。失敗したら20ms置いて3回まで要求する)を解析する。解析は、Push/Popを含むグローバル項目、4バイト形式のUsage、レポートIDごとのビット位置を扱い、X、Y、ホイール、AC Pan、ボタンの変数フィールドだけを保持する。保持しないフィールドも、後に続くフィールドの位置には長さをすべて加える。相対のX、Yは、Logical Minimumが0以上と書かれていても符号付きとして読む。移動量は両方向にあり、符号なしとして読むと左や上への小さな移動が画面の端まで飛ぶためである。X、Yは同じレポートのものを組にし、相対のものを絶対のものより優先する。ディスクリプタが使えないブートサブクラスのマウスは、ブートプロトコルに切り替えて3から4バイトのレポートを読む。

ディスクリプタどおりに読むブートサブクラスのマウスには、SET_PROTOCOLでレポートプロトコルを要求する。ブートローダがブートプロトコルのまま残した機器が要求に従わないことがあるため、3から4バイトのレポートで、ディスクリプタにないレポートIDで始まるもの、またはディスクリプタのX、Yがその長さに収まらないものが来たら、以後はブート形式として読む。

インタラプト転送の長さは、ふつうはwMaxPacketSizeとする。ポインタのレポートがそれより長いときは、ディスクリプタにある最長の入力レポートの長さ(64バイトまで)とし、複数のパケットに分かれたレポートを1回の転送で受け取る。ポーリング間隔は、LowとFull SpeedではbIntervalをミリ秒として2のべき乗に切り捨て、High Speed以上では2^(bInterval-1)マイクロフレームとする。転送の誤りでエンドポイントが停止したら、Reset EndpointとCLEAR_FEATURE(ENDPOINT_HALT)で再開する。正常な転送を挟まずに8回を超えて停止したら、再開をやめる。ポインタは、ディスクリプタから読み取った配置と最初の12個のレポートをシリアルに出力する(`usb: hid:`)。

## 6.5 サウンド

サウンドデバイス`snda`は、B-right/Vのサウンドデバイスの仕様(データ番号と構造体、`include/ts/snd.h`)に従う。その仕様向けに書かれたプログラムはそのまま使える。

| データ番号 | 内容 |
| --- | --- |
| 0、1 | 再生するPCMを書き込む。録音したPCMを読み出す |
| `DN_SDPCMMODE` | サンプリングレート(8kHzから48kHz)、形式(μ-law、8bit、16bit)、モノラルとステレオ |
| `DN_SDPCMCTL` | 停止、再生、録音、繰り返し再生 |
| `DN_SDPCMCNT`、`DN_SDPCMENDCNT` | 処理したバイト数と、停止するバイト数 |
| `DN_SDPCMBUFSZ` | PCMバッファのサイズ(デフォルト32KB、最大1MB) |
| `DN_SDGAININ`から`DN_SDVOLAUX2` | 入力と出力の音量 |

チャネルはプロセスとユニットの組ごとに1つ持ち、複数のプログラムが同時に鳴らした音はミキシングして出力する。

ブザーとキーやボタンのクリック音は、音箱にある音の実身(ブザー音、押下音、離し音)をサウンドデバイスで再生したものである。音の実身のレコード1にWAVがあればそれを、なければメタデータにある音の高さと長さから生成した音を再生する。

## 6.6 ドライバの規約

- デバイスに渡すアドレスは物理アドレスである。リニアマッピングの外にあるバッファは、`ConvPhysicalAddress`で連続する区間ごとに物理アドレスを求める(4.6)。
- 割込みハンドラが参照するデータは、割込みを許可する前に用意しておく。
- ドライバ内の排他制御はスピンロックかミューテックスで行う。割込みを禁止するだけでは他のCPUを止められない。
- 期限を過ぎた時刻をコンペアレジスタに残すと割込みが連続して発生するので、設定する前に確認する。
